| 每池线程 | operator CPU / wall均值 | init CPU均值 | 首波全部开始时间均值 | 首波stage0 callback跨度均值 |

128线程下callback墙钟较长、首波结束跨度较长，但整request均值并未出现相同比例的差异。这说明局部时间不能直接替代request关键路径；没有内核runq或硬件计数，不能将wall−CPU精确归因为调度等待或cache miss。首波全部开始时间以最早记录提交为起点，callback跨度以最早开始为起点，两者不是同一时间边界。

短工作仍保留初始化/首次触页、控制callback、提交和维护成本，CPU/请求不必降至原工作的1/8。这里测得约1ms算子只是S敏感性档位的结果，**不是旧trace约0.85ms线程活跃周期的验证，也不是生产算子标定**。当前无需继续调iterations使其更接近某个历史数字。

| 每池线程 | trace1−trace0请求均值 | 整轮CPU/请求增量 | 样本p99增量 |
|---|---:|---:|---:|
| 16 | +0.294ms / +1.637% | +3.273ms / +1.830% | +1.962ms / +9.143% |
| 128 | +0.402ms / +2.238% | +4.069ms / +2.281% | +2.327ms / +11.038% |

短工作下观测差已与此前Q/O约1%的均值差同量级或更大，所以后续性能排名保持trace0，trace1只用于有明确问题的机制诊断。这里不是Q/O评分成本：home绕过L2评分，两个trace档仍维护基础计数和生命周期。差值包含额外记录及其对调度的反馈，也不包含构造期线程池/trace缓冲分配和运行后CSV导出，不能换算为单次探针的固定纳秒或所有计数维护的成本。

历史长工作下的比例较小只能作为背景；两批不同期，不能定量将差异全部归因于任务变短。当前每对只运行一次，不能给出成本置信区间；p99尾端仅约两个请求，+9%～11%不能当作固定追踪税率或生产尾部损失。

## 4. 没有请求重叠，仍有明显的请求内部排队

regular12QPS的计划间隔约83.33ms，四轮观察到的request峰值并发为1。S减小了每request工作需求，而请求到达没有增加，因此本批是孤立request内部扇出的校准，没有覆盖多个request共同竞争。

这不等于池内无压力。初始80个算子仍连续ready，首波记录提交跨度均值约0.061～0.062ms，远短于约1ms算子CPU。两档分别有96.391%/96.174%的operator提交样本Q非零。已选池Q/C与开始前等待存在下列描述性关系，单位ms：

| Q / 名义容量C | 16线程 wait p50 / p99 | 128线程 wait p50 / p99 |
|---|---:|---:|
| 0 | 0.003 / 0.017 | 0.004 / 0.016 |
| (1,2] | 1.057 / 2.015 | 1.068 / 2.077 |
| (2,4] | 4.031 / 5.209 | 3.953 / 5.088 |
| (4,8] | 4.424 / 5.414 | 4.382 / 5.369 |

这是本合同内的“负载桶→callback开始前等待分位”，不是“线程池负载→request p99”的通用预测式。等待起点在选池/预留/诊断读取之后，包含底层add、Folly等待及callback开始前调度；Q不是内核runq。桶混合不同角色和长短工作，同request样本相关，不能作因果回归或推导最优阈值。

128线程下`Q=0、I>16、O>16`仅5/32256个提交样本（0.016%），该桶wait p99仅0.004ms。16线程下`Q>0、I≤16、O>16`有27642个样本（85.696%）。因此当前仍没有证据表明Q盲区主导等待，也不能只用I是否超过容量识别积压。比例来自非原子、分开读取的提交样本，不是时间过载比例或原池误判率。

**继续保留Q与O，不因短工作就引入持续性门控或修改阈值。** 本批home没有执行借出，无法判断二层均衡的短工作净收益；单池callback峰值16或25～28也不能称为等量CPU同时运行。

## 5. 下一步：六轮SD请求密度对照

执行[短工作SD六轮指南](TARGET_V2_SHORT_DENSITY_GUIDE.md)：保持S每request图/计算/数据/亲和，将regular到达提高至96QPS、1920请求，使投递期仍约20秒；同批home/Q/O × 16/128线程、seed421、trace0，共六轮。

选择它是为了覆盖当前缺少的request重叠，并直接测SD合同内的借出净收益，避免先在明显孤立的S上再跑一轮排名。8倍QPS是预先声明的敏感性档位，理论迭代/访问需求接近原L，不代表实测CPU需求相等、真实12QPS业务或持续饱和；短工作的固定成本也随请求数增加。是否出现重叠及竞争必须由实际peak、lag、backlog和时延确认，不能按QPS直接宣布。

六轮后即分析，不自动提高QPS或增加trace；保留同批home、失败及完整投递窗口。它不产生S到SD的完整策略差中差、不验收生产p99，也不需要为贴合旧trace重新采集。若候选收益难以区分，则结束该族；若有明确反例，才选择对应的有限诊断。

模型主线仍为每核实cluster一个子池、L1 request home、L2新ready选池、同NUMA优先。异步RPC恢复、同步阻塞、共享数据及跨NUMA仍是不同覆盖项；[v2异步设计](ASYNC_CONTINUATION_WORKLOAD_DESIGN.md)尚未变成驱动能力，不能把本批当作这些项的验收。本次只更新证据、结论与指南，不改运行负载或调度代码，无需重编。
