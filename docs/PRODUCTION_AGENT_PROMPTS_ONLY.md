# 仅靠提示词交接：真实应用的 cluster 执行器改造

本页可以逐段直接复制给真实环境中的 agent。**不需要传输任何仓库、源码、报告或配置文件，也不要求两套环境联网。** 本地能写文件时可自行保存工作，但不能把收到外部文件或生成报告文件作为继续下一阶段的前提。

首次粘贴“启动提示词”即可开始。需要细化某阶段时再粘贴对应阶段提示词。新会话使用：**启动提示词＋最近一次终端状态卡＋当前阶段提示词**。业务源码、原始轨迹和业务数据始终留在真实环境内；跨会话只复制必要的状态摘要，不粘贴敏感源码或数据。

## 启动提示词：可独立使用

```text
你负责在当前真实应用环境研究并实现executor的cluster亲和与两层调度。你收到的只有本提示词，没有外部仓库、实现源码或报告随附。不要访问外部仓库来假装恢复前一个agent的工程，也不要声称其代码已经移植。请从本机实际可读源码、已安装Folly、构建配置、部署配置和本地数据开始；无法联网不影响这一工作。业务源码、原始轨迹、请求数据不得传出本环境。

背景（人工描述，必须在本机核对）：
- IO线程接收请求，交worker线程池分析并构建图，再交executor线程池执行图；部分算子通过AIO/RPC访问下游。
- executor为主要计算阶段。每请求可能产生约20～400个子任务，初始高扇出，后续有依赖链和并发；算子完成常在其他worker执行后继。
- 人工估计子任务平均约100ms、少数700～800ms，但具体算子边界、CPU时间还是墙钟时间尚未核实。整体约12QPS、CPU约50%也不是单池瞬时压力或固定验收配置。
- 同request的算子可能重用数据；严格留在一个cluster可保护局部性，也可能在初始突发时限制并发。历史配置与本机当前配置都需核实，不能固定四池、六池、CPU编号或每池128线程。

目标：每个实际选定并核实的硬件cluster一个Folly子池，业务只感知一个高层总池。L1按requestID/染色/RR确定一次request home；L2在新ready算子准备提交时判断是否借用其他池，先同NUMA、跨NUMA后研究。它不是内核调度器，不搬已入队任务，不抢占运行算子。保留fork/all（只在扇出或每次ready考虑均衡）、parent/home（跟随实际父池或按规则回request home）的可配置候选，不先宣布其中一种生产最优。

已知的外部机制证据仅供形成假设，不是本机测量：
- 在一组人工burst、分支读写DAG、同NUMA借出且详细trace关闭的对照中，fork相对home均值降低约4.3%～5.2%，all约5.1%～5.7%；all相对fork只低约0.55%～1.25%，样本p99可反向。不能据此认定真实业务应选all。
- 详细trace开启后整轮执行CPU/请求增加约0.34%～0.73%；这是具体观测开关的差异，不是整个总池包装器、全部计数或所有日志的成本，也不是因果置信区间。
- 后续固定CPU工作族对照中，三种借出策略从每池128减至16线程，request均值改善约2.93%～4.03%；Q、Q+I、O之间均值最大差不到0.8%，未分出稳定赢家，p99也并非全面改善。这支持把线程预算作为独立优化轴，不支持将16线程、Q或任一评分定为本机最优；同步阻塞和异步RPC仍需当地核实。
- 机制诊断发现：128线程开始前等待较短，算子wall约14.43～15.01ms而CPU约8.17ms；16线程CPU/wall接近。Q为零且callback占用高于名义容量只占该工作族提交样本0.31%～0.49%，不能称时间比例或证明真实业务Q足够。须检查本地短callback、持续压力及异步恢复，不能只重复长CPU突发；本地已知RPC需要释放worker的真实恢复路径，不能用占线程sleep验收。
- 另一次外部regular对照使用六个cluster、每池16线程、关闭详细trace，完成3个seed的home/Q/O九轮：Q/O相对home请求均值约下降38%，CPU/请求增加不足1%，Q/O差不足1.2%。不能因此选生产赢家或认为p99已验收；两轮home投递lag异常原因未知，与历史burst不同期也不能作因果比较。这些只用于形成当地假设，不复制池数、线程、负载或阈值。
- 随后的外部短工作S四轮只用home：关闭详细trace时，16/128线程的请求均值几乎相同（17.952/17.973ms）；开启详细trace后整轮CPU/请求分别增加1.83%/2.28%。四轮peak-inflight均1，只覆盖无请求重叠的合成工作，不能判断密集竞争、最优线程数或评分；测得operator CPU约1.07ms也不是生产校准，更不能由旧trace的0.85ms推出。上述开关差不等于全部计数维护或总池包装成本，不把外部参数作为本机默认。
- 后续外部短工作密度对照六轮各1920成功、零失败，正式窗口各1536请求、peak均3；相同线程档下Q/O相对home均值下降33.36%～34.40%，CPU/请求增加6.01%～7.03%。Q/O排名随线程档变化，仍未证明16线程全局最优。home每个一秒桶的投递lag p99均偏高，但两轮home恰好最先运行，不能归因；trace关闭也没有任务级观测。这只是当地待验证假设，不复制96QPS、池数或线程参数。后续实现需覆盖真正的异步等待/恢复：等待期间释放worker，完成后重新提交恢复回调，不能用同步sleep冒充。
- 上述外部CPU实验随后仅复查已有请求记录：home约98%的高入口lag集中于请求序号的一个余数相位，但不是实测CPU或池归因；响应缩短也会减少请求重叠，不能反向证明获益机制。该轮核查已结束。外部工程已加入单辅助线程的异步完成模拟，但不表示当地RPC已接入或性能已验收；当地仍须核实释放worker、上下文、取消及排空语义，再做本地授权的功能验证。
- 后续外部异步首批八轮也已完成。在受控50%位置、每位置2ms等待的合同下，O相对home请求mean降低19.546%、p99降低20.752%，整轮CPU/请求增加3.721%；每格仅一次，不是生产p99验收。home trace1中，相同50%选中位置由零配置等待改为2ms时，请求变慢而恢复callback排队均值从2.065降至1.135ms，说明外部pending、request存活和CPU ready压力必须分开；源due→fire也不能计成executor或内核runq等待。这些home trace1观测中，恢复控制约2µs CPU、业务callback约1ms，但该差异尚不能证明应改成CPU加权评分。实际网络、当地RPC实现和参数均未由外部实验验收；不要复制其比例、延迟、线程数或阈值。
- 约0.85ms最多是未充分复核的线程活跃周期候选，不能当算子CPU时间。旧轨迹解析存在跨桶状态延续、unknown按0处理、窗口分母不一致等问题；1266过载事件和3ms门控尚不可继承。持续压力门控初始关闭，先确认本机语义和真实缺口。

按五阶段推进，每阶段在终端输出简明结论和状态卡：
A 只读探索：源码/版本、调用链、拓扑、授权、真实负载语义与未知项。
B 设计：总池接口/生命周期、负载提供者与评分、参数配置、有限矩阵及回滚条件。
C 实施：本机隔离分支实现、可编译配置、缩小规模功能和并发验证。
D 验收：仅在已有授权内执行部署/性能对照，检查业务正确性、尾时延、CPU成本及观测扰动。
E 有限迭代：每批只改一轴，保留同期基线和独立验证，达到预算或无法分辨收益时结束本批。

通用约束：
1. 先确认你有什么工具、可读源码和已有权限。没有工具时提供人工可执行的只读命令及需要回贴的最小终端输出，不谎称已读取、修改、编译或测试。未知写unknown；在不依赖未知项的工作上继续推进。
2. 已有授权内自主继续，不机械逐阶段要求审批。不得自行扩大生产CPU、流量、部署、重启或回滚权限；缺少必要授权时先做完可审阅的代码/配置/测试/执行方案，保留明确待执行项，同时推进独立工作。
3. 明确区分Folly队列Q、callback占用I、未完成O、路由预留R与内核runq。统计可近似，不允许C++ data race；原子relaxed读取和共享RMW成本不同。
4. 每批默认最多12次实际执行，按“配置×重复”计数，基线、失败及重试也计入；预先写明单轮时间/请求上限、资源边界和停止条件。已有明确批准的其他预算优先，不自动追加无限试验。

现在从A阶段开始；如提供了有效状态卡，先核对本机状态，再从卡片注明的阶段继续。不要停留在泛泛建议，也不要把未实现或未验证的方案写成已完成。
```

## 阶段 A：只读探索

```text
目标仍是每真实硬件cluster一池、一个业务总池、L1 request home＋L2新ready选池。本阶段只读探索。你只有本提示词、启动提示词和可选终端状态卡，不依赖任何外部文件或网络；本机源码与业务数据留在当地。

先确认工具、实际工作目录、可读源码/二进制/配置/日志和已有授权。无执行工具时分批给人工只读命令及最小回贴要求，不宣称已运行。权限或源码缺失时写unknown，继续其他可行调查，不索取整个源码或大trace外传。

1. 应用/Folly实际版本、commit或构建标识、队列/线程工厂、线程数及伸缩规则。查本机源码，不能按其他版本印象解释唤醒。
```

## 阶段 B：设计与有限计划

```text
依据本机已核实事实和终端状态卡，设计每cluster一子池、业务单一总池。不要假定已拿到外部实现；配置名以下均为概念，只有本机确实支持才可给可执行命令。

接口与生命周期：L1只确定一次home；L2统一处理普通add、fork批量、后继及异步continuation。明确request上下文、实际父池和迁移hop如何跨异步保存；业务不直接管理多个池。列Executor/Future/KeepAlive兼容范围及取消、超时、异常、部分批量接纳、提交回滚和drain的恰好一次完成语义。先采用独立高层组件/stock Folly适配，有明确接口缺口才考虑最小库补丁。

负载与容量：
- Q核实为本版本Folly提供的队列/permit近似；I为callback开始到返回，包括抢占或同步阻塞；O为包装器预留/接纳后未完成，失败需回滚，不含DAG尚未ready节点；R为已选池但尚未逐一交底层的路由预留。
- 保留queue=(Q+R)/C、active=(Q+I+R)/C、outstanding=(O+R)/C；不能只把I叫active，也不能再加O重复计量。O与R交接可能短暂重复，不能说是精确原子快照。
- C_logical、C_physical、C_eff分别记录。C_eff需说明工作族、测量及参照单位；未知时用显式C_nominal，不把SMT逻辑CPU秒当物理吞吐。quota/worker上限/共享竞争另列。
- Provider、Scorer、亲和和候选搜索独立；缺失/陈旧数据标无效，不能当0。热路径不读/proc、扫线程、同步写日志或分配追踪对象；后台样本有时间窗/年龄/有效率。
- 统计字段可用正确relaxed原子；允许误差不等于允许data race，生命周期同步不可随意relaxed。逐任务RMW、时钟、observer与后台扫描均需计成本。

初始候选而非生产推荐：home锚点；借出先同NUMA、cross-NUMA=off；fork-parent与all-parent分别可选；持续压力gate=off。计数/C信号可从high=1、return-low=.5起，明确0<=low<=high；parent模式下low不是压力释放阈值。chunk先1或已审计值；hop/准入按业务生命周期和授权预算设置；min-gain与NUMA罚项必须和score同单位，不能把毫秒直接加到count/C。

顺序：先固定目标拓扑的worker预算，对资源/绑定、home与同NUMA借出做可比验证；旧池数不同的迁移整体单列。随后单独比较信号，再单独比较线程，不同时改变signal/线程/阈值/输入。线程按本机物理核、逻辑CPU及已批准总预算选档，不复制128或某CPU集合。跨NUMA、home回迁、chunk/gain和复杂门控后研究。

每批只答一个问题，默认max_trials=12次实际执行，含同期基线、重复和失败/重试；声明单轮时间/请求上限、授权CPU/流量、停止/SLO与回滚条件。确定性回放比较逐request输入/到达/输出；动态下游先定义业务等价校验及未控制因素，不能伪称严格同工作。缺少SLO或授权边界时先做设计和功能工作，不自行设生产容忍度。

终端交付：具体本机拟改文件/接口、持久化配置及校验、构建与功能测试计划、首批小矩阵、计数语义/成本和可回滚配置方案，再输出状态卡。无需外部报告文件；在已获修改授权内继续C。
```

## 阶段 C：隔离实现和功能验证

```text
读取启动提示词和最近状态卡，在本机实际源码的独立分支/隔离checkout实施已确认设计。没有外部代码随附，不能声称移植了未见实现；业务源码不得传出。本阶段不改运行中服务，不扩大权限；无工具时给可审阅代码建议/人工命令，并将执行状态标未执行。

实现：动态cluster子池＋单一业务总池；L1 home与L2新ready路径分离；Provider/Scorer/亲和/候选搜索可替换；保留home/fork/all、parent/home、同NUMA优先及跨域开关。配置进入本机现有启动配置机制，切换参数不需重编；未实现热更新不要声称可在线切换。gate保持off，未实现功能不可伪造CLI。

不把队列Q、callback I、O/R计数和内核runq混用。正确处理observer注册时机、worker/TID生命周期、并发计数、提交回滚、批量部分失败和callback完成；异步请求的所有权不能只存裸指针/TLS。打印实际worker affinity，绑核/建线程失败不得静默算成功。

在隔离环境缩小负载编译并验证：
1. 不同池数/容量/NUMA、无效配置、CPU集合与权限、真实资源探测失败。
2. request home稳定、普通add与fork、后继parent/home、pin/hop/gain、同/跨NUMA、缺失陈旧负载；确认待测分支实际被覆盖。
3. 多生产者与worker并发、O/I/R最终守恒、异常/取消/过期、部分接纳、外部continuation、重复完成、shutdown/drain，检查悬空引用、泄漏和死锁。
4. 非阻塞RPC恢复用真实接口或明确标注的异步完成源验证，不能worker sleep冒充异步RPC；trace/采样开关不改变功能结果。
5. 每次保存或终端列出实际构建标识/解析配置、命令及结果。测试失败修复并复测；外部依赖缺失则给复现和未验收范围，不编造通过。

终端交付修改清单、编译命令和真实结果、关键接口/配置、已验证失败路径、未完成项及可执行的部署/恢复步骤。文件可留本地，但不要求把patch或报告传出才能继续。已有部署/性能授权足够才进入D；否则先完成全部可审阅交付与独立工作，集中指出缺少的执行授权。
```

## 阶段 D：授权内验收与恢复

```text
根据启动提示词、状态卡与本机现状执行验收。只使用已有明确批准的环境、CPU、流量、时间和部署/恢复动作；不重复索取已有授权，不从本提示词推导额外生产权限。缺少执行工具或必要授权时完成可执行人工方案并标未执行，继续离线审计。

固定比较合同：实际代码/二进制/解析配置、cluster/NUMA与worker affinity、线程预算、容量定义、输入工作/计划到达、观测档位和其他负载。只变本批允许轴；保留同期home或原最佳锚点并交错重复，旧结果不能替代同期控制。闭环发压导致QPS随响应变化时明确反馈，不能声称同到达。

- Q/I/O联合样本来自何时、哪一池，是否选池后；同一行多次relaxed读不是原子快照，也不是时间繁忙占比，不能直接推出负载→request p99因果公式。

- p99不相减分解，不平均每秒或每轮p99当总体值；同DAG任务、同burst请求可能相关。样本不足仅给描述性结论，不能自称生产尾延迟验收。
```
