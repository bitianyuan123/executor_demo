# 4013 机制结论与负载覆盖边界

**当前状态：4017已完成六轮既有CSV的到达核查，见[结论](TARGET_V2_4017_REVIEW.md)。不再重跑CPU矩阵、到达诊断或追加trace/阈值。异步完成源与驱动已加入工程，当前按[异步功能指南](TARGET_V2_ASYNC_FUNCTIONAL_GUIDE.md)进行编译及小规模功能验收；等待期间释放worker，恢复callback再推进图。性能对照待功能验收后另立合同。目标始终每个已核实硬件cluster一个池。** 下文保留当时证据/命令，不是新的执行清单。

六轮诊断完成，可以结束当前固定CPU突发负载的重复诊断。**较多线程使callback更早开始，却伴随更长的callback墙钟；Q和O都实际触发大量同NUMA借出，而本负载很少在Q为零时提交到高占用池。** 因此现有结果不能证明O优于Q，也不能证明Q已足够覆盖真实业务。

需要扩展负载覆盖，保留现有基线供回归。近期先做[16线程regular到达守护及分步覆盖计划](TARGET_V2_COVERAGE_NEXT.md)，之后有界推进短callback、持续竞争和外部等待工作族；不继续围绕同一burst合同堆叠信号/阈值。已知业务包含异步RPC，新增[独立实现设计](ASYNC_CONTINUATION_WORKLOAD_DESIGN.md)，明确这是v2驱动尚未覆盖的结构。

## 1. 证据完整性

来源为用户终端4013.log，SHA256：`c045f001126d82c29399799c4ea0aec296f236a1e17942cb293242525b999f78`。[机器可读摘录](../results/review/4013_summary.json)保留打印精度；未取得目标机原始CSV重新计算。合同来自[六轮诊断指南](TARGET_V2_SIGNAL_DIAG_GUIDE.md)。

- home/Q/O × 16/128线程，seed421；六个已核实cluster各一个池，两档C均16，NUMA0/2。命令仅policy、threads、output变化。
- burst8、12QPS、宽80/4、深2/2、分支64KiB、task级长短扰动、all-parent、同NUMA、trace1；CPU后台采样关闭。除trace外沿用4012对应合同。
- 六轮整轮240/240成功，正式计划窗口`[2,18)`各192请求、24完整burst，peak-inflight均8；工作签名、arrival hash和checksum一致。
- 每个request-cohort有32832个callback；本批按task提交窗口筛出的32256个operator也完整。两者筛选口径不同，不能一般化为永远相等的样本集合。
- 实际burst attempt跨度均值0.693～0.695ms、最大0.695～0.700ms，整轮lag p99为0.059～0.061ms。attempt在request构造/root add之前，不能代替算子ready时间。

这是单seed的trace1机制诊断，不能与4012的trace0合并成性能重复、估计独立trace成本或给出正式p99保证。4012仍是本轮信号/线程的主要性能证据。

## 2. 更多worker并没有等价地增加计算进展

下表request时延为正式cohort；wait是选池后提交到callback开始，包含add、队列和开始前调度；operator CPU/wall包含后继提交。单位ms。

| 线程/策略 | request mean / p99 | callback wait p99 | operator CPU / wall均值 |
|---|---:|---:|---:|
| 16/home | 157.530 / 227.492 | 81.271 | 8.135 / 8.155 |
| 16/Q | 146.024 / 197.570 | 67.981 | 8.151 / 8.171 |
| 16/O | 145.379 / 190.936 | 67.188 | 8.142 / 8.175 |
| 128/home | 160.173 / 226.132 | 71.868 | 8.171 / 15.007 |
| 128/Q | 151.277 / 198.169 | 58.090 | 8.181 / 14.660 |
| 128/O | 151.492 / 205.922 | 58.467 | 8.186 / 14.430 |

三种策略均出现：128线程开始前等待更短，callback墙钟明显更长，request均值却更差。16线程的单池callback占用峰均16；128线程为47～59，占用包括被抢占或阻塞的callback，不是onCPU。

首波stage0的callback跨度均值（最早开始到最后结束）也有相同方向：

| 每池线程 | home | Q | O |
|---|---:|---:|---:|
| 16 | 57.845 | 41.190 | 40.544 |
| 128 | 96.682 | 82.857 | 82.402 |

128线程首波全部开始更早，却结束跨度更长。这一跨度不包含之前排队，不是整个request关键路径，也不能证明16CPU持续占满多少ms。

**可以确认“更快领取/更早开始”不能单独作为优化目标；应评价整request进展、CPU成本和尾部。** 现象与线程过配竞争相容，但没有内核runq或硬件缓存计数，不能将全部wall−CPU直接记为runq，也不能精确声称等待从Folly队列搬到了内核。

## 3. Q盲区存在，但未成为本工作族的主要判别场景

128线程下，同一operator提交行的`Q=0、I>16、O>16`为：

| 策略 | 样本数 / 总operator | 提交样本占比 | 该桶wait p99 ms |
|---|---:|---:|---:|
| home | 120 / 32256 | 0.372% | 1.144 |
| Q | 157 / 32256 | 0.487% | 0.794 |
| O | 100 / 32256 | 0.310% | 1.011 |

与此相对，三组128线程在95.247%～95.691%的提交样本里Q仍非零。本批有大批连续投递，Q仍经常暴露等待工作；Q/O净效果接近有了机制上的解释线索。**不能把盲区“存在”升级为“主导尾时延”，也不能从本批较少出现盲区推出真实业务中同样少见。** 这些少量样本的尾分位尤其不稳定。

16线程没有I>16样本；`Q>0、I≤16、O>16`占88.678%～88.963%。因此仅用I是否超过CPU容量，在受限worker配置下会遗漏大量尚未开始的工作。现有active评分本来就是`Q+I`，不能把它与“I单指标”混为一谈。

上述比例是已选池的提交事件比例，不是时间繁忙比例。Q/I/O分开读取，不是原子快照，未包含评分时全部预留R；Q/O策略会改变样本所落的池。不能计算原池误判率、离线精确重放score或建立统一request p99公式。原生Q、I/O计数均继续保留，当前无依据改默认阈值、增加3ms门控或把proc扫描放入热路径。

## 4. 借出已实际发生，parent也可能普通路由回home

以下为正式request-cohort，非前段整轮运行摘要：

| 线程/策略 | source≠chosen | 首波stage0借出 | 普通后继借出 | source非home而chosen为home |
|---|---:|---:|---:|---:|
| 16/Q | 15248 | 9194 | 6027 | 1859 |
| 16/O | 15760 | 9551 | 6108 | 1918 |
| 128/Q | 14813 | 8638 | 6174 | 1762 |
| 128/O | 15099 | 8960 | 6130 | 1743 |

home组跨池0，全部六组跨NUMA0。借出并不只发生在初始fork，普通后继也有明显路由变化；不能把Q/O相近解释成二层均衡没有激活。

本合同中`source≠chosen`数量恰好等于LocalSpill原因数，但二者定义不同。ReturnHome原因均0；最后一列是普通LocalSpill可能选回home，**parent表示以实际父池为偏好，不表示永久禁止回home**。本批没有证明这些路由变化都值得，也没有测得缓存miss成本；少量HopBudget限制不构成放宽hop的依据。

## 5. 历史轨迹怎样改变覆盖，而非决定模拟参数

4005等旧trace支持短时服务集中、历史未绑核池可短暂获得远超一个cluster的CPU服务，以及多池同期竞争的研究价值。因此必须保留目标cluster下的突发、过配、短时反馈与共同竞争维度。

但旧trace没有request/operator/RPC身份；window unique-onCPU不等于I，线程活跃周期不等于算子CPU。4010新增状态解析还有已记录缺陷，0.85ms、1266事件及3ms阈值不能用来校准当前工作量。历史四池不决定目标池数，目标始终是实际选定的每个硬件cluster一个池。

当前模型的已测operator CPU约8ms、批间有空档、名义需求约17%的96逻辑CPU预算，不能宣称复现“真实微突发”或全应用50%CPU。初始80个算子连续ready、固定64KiB分支、无异步RPC也不是生产画像。**调整应表现为增加独立敏感性工作族，明确哪些机制结论会失效；不覆盖旧基线，也不以调到某个历史峰值作为验收。**

## 6. 已收敛结论与下一步边界

- 已收敛：这一CPU分支工作族下，同NUMA借出比严格home更有利；线程数量必须独立调优；Q/I/O各有语义边界，Q仍是有用基线；当前证据不足以支持更复杂的评分/持续性门控。4012的trace0三seed结果和4013机制证据分别保留。
- 尚未收敛：生产最优线程数、Q/O胜负、fork/all的全局选择、短callback成本、持续竞争容量、同步阻塞/异步RPC、共享数据与跨NUMA成本、正式p99。它们需要不同的实验合同，不能靠继续重复同一burst解决。
- 当前仅执行[9轮regular守护](TARGET_V2_COVERAGE_NEXT.md)，检查16线程简化候选是否只适合burst；不重跑4012/4013。之后按覆盖计划选择一个工作族，不自动生成所有维度的笛卡尔积。
- 异步RPC是已知结构，不等待旧trace补出参数才设计；[实现设计](ASYNC_CONTINUATION_WORKLOAD_DESIGN.md)先定义生命周期和功能验收，尚无新增CLI或ARM性能结果。阶段5仍优先高层组件复用，未出现必须修改Folly核心的新缺口。

本轮交付更新结论、覆盖次序、纯prompt交接及终端摘录。运行负载和调度代码不变；新指南做命令语法与计划合同验证，不把开发机检查称为ARM性能测试。
