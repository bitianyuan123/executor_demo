# 历史 trace 的时间形状补证：可直接交给持有原文件的 agent

用途：在选择新的合成负载形状之前，补齐**池级 CPU 服务背景、集中段、复发及同期活动**的时间约束。既有汇总不足以确定逐请求的先扇出、后续执行和请求交叠，不能据此指定 `80×1+4×22` 或其他图为现场模型。本提示词只需要持有历史 trace 或已有派生产物的分析环境；不要求访问真实业务、业务代码或重新采集。目标架构仍是每个已核实的硬件 cluster 一个池，历史四个未绑 CPU 池只是采集条件。

将以下整段复制给分析环境中的 agent 即可。无需把本仓库或其他文件传入该环境；找不到原产物时，先报告已有证据，不凭空填写。

```text
请对本机已有历史调度轨迹做一次有界、只读的时间形状补证，回答：CPU 服务集中段出现前后，池内和其他池有多少持续背景；集中段如何间隔、复发、重叠。这些信息将约束之后的合成场景设计，本次不选择新 DAG、不调整调度策略或阈值、不运行合成负载。

一、环境、证据和停止边界
1. 仅使用本机已保存的旧 trace.log、映射、解析代码及派生产物。不访问真实业务环境或代码，不读取当前 /proc 来推断旧进程，不重采 trace，不改系统配置，不联网。可以在新目录写派生结果，禁止覆盖原产物。最终只打印不超过 100 行的摘要，原始大文件留在本机。
2. 历史采集条件为四个未绑 CPU 的临时 executor 池，用户报告 16 QPS；QPS 不是 sched 事件测得。目标设计是每个真实硬件 cluster 一个池，当前独立测试选择六个 cluster。禁止把历史四池重新分组或等比例放缩为六池，禁止以 16 CPU 为历史池硬上限，也不从这次分析选定迁移阈值。
3. 优先复用已验证的 S1 summary_exact.json，schema=sched-text-v1，含完整共同时间窗的 1ms windows.series。旧路径可能是 /data/workspace/rank_trace/results/sched-review-2/summary_exact.json；路径不存在时，只在已有分析工作目录查找对应产物。列实际使用的输入路径、文件 SHA256、解析代码版本/哈希、绝对窗口 [start_ns,end_ns)、池映射来源。原trace未读取时沿用已保存的来源哈希并注明；不为补哈希另扫原文件。终端文字报告不能冒充原始 series。
4. 已知主口径为同一 10s 窗：各池 mean matched onCPU 为 7.093/4.364/6.620/6.569 个逻辑 CPU 当量，1ms 峰为 78.437/73.656/72.167/78.559。最忙 10% 桶承载各池 45.532%–54.827% 的 CPU 服务；其余 90% 桶的补集为 45.173%–54.468%，这是时间桶分布，绝不是每请求尾部占比。2 倍自身均值的高服务段，已报告 p50=2ms、p95=15–20ms、max=25–55ms。它们是核对参照；不要求新计算通过调整口径得到相等结果。若窗口、映射或规则不一致，先解释差异。
5. 保留 coverage=unknown、时钟未知、名称推断映射和匹配区间删失限制。源文件可见 384 个记录 CPU 不证明完整覆盖；没有 LOST 文本也不证明无丢失。没有 request/operator/RPC 标记，不能恢复请求到达、DAG、算子时间、数据亲和、请求尾部或业务 p99。

二、输入验证和唯一必要时的回退
6. 验证 series 各池共用绝对起止时间、桶边界和数量，start_ms/span_ms 连续且有限；observed_demand>=oncpu_cores>=0。检查存储截断、window_storage_limit_updates_skipped、缺行、乱序与源 audit。末尾不足完整桶的片段剔除并报告长度。缺失/损坏桶不能补成空闲；零匹配服务也只能叫“未观察到匹配服务”，不能叫真实 idle。
7. 不使用 4010 外部 S3 bounded_gap_scan.py 的完整 N(t) 或桶结果。它曾有跨桶只更新首桶、重复 runnable 计数、非 R 切出未清等待、未知初态缺失和乱序被接受的缺陷；全局均值接近不验证其分桶。
8. 若已有可信完整 series 足够，禁止重扫原始文件。仅在 series 缺失且已有原始 trace 和映射时，才允许一次有界流式解析，仍使用既定 10s 绝对窗口。先用小型合成事件验收：跨 2.5ms 的运行区间分别贡献 1/1/0.5ms；缺 switch-in、重复 wake、R/R+ 抢占、迁移、乱序、左右删失均有明确失效/删失规则；等待计数不泄漏，单线程运行时间不超过区间墙钟，桶积分与总积分守恒。未通过就停止，不以未经验证的新 parser 生成结论。
9. 流式回退不得把全部事件装入 DataFrame；限制为一次文件扫描、最多 10 分钟和 1GiB RSS，SHA256 可在同一读取中累计。超过限制、缺映射或绝对窗口不确定时，报告 unavailable 和原因，不自行重试多种口径。未知状态保留 unknown；只统计闭合且有效的匹配区间，不宣称完整 runnable 重建。

三、共同定义：描述 CPU 服务，不能解释为在线繁忙判据
10. 对池 p、完整固定桶 k，定义 S_p[k]=匹配 onCPU 时长之和/桶宽，单位“逻辑 CPU 当量”；A_p[k]=S_p[k]×桶宽，单位 CPU·ms。D_p[k] 为已有 observed_demand，W_p[k]=D_p[k]-S_p[k] 仅表示保留下来的闭合等待区间贡献，不是完整 runq 或 Folly Q。没有可信 D 就标 unavailable，不用 0 替代。
11. 分别在 1/5/10ms 完整共同桶上分析。可由 1ms 序列按共同起点合并，S、D 按服务面积相加后除新桶宽；waking 是计数可相加，unique-TID 不能相加或平均，等待均值不能无样本数加权合并。每种桶宽报告实际分析时长；若截尾使窗口不同须明确，不把桶宽效应与窗口变化混为一谈。
12. 令 mu_p=该共同窗口中 S_p 的时间加权均值。高服务桶 H_p^m[k]=(S_p[k]>m×mu_p)，仅用 m=2、4；mu=0 时该池没有可定义的相对高服务段，标 unavailable。高服务段为连续 true 桶，无间隙合并；左右接观察边界者标删失，不能把边界当实际开始/结束。
13. 阈值依赖整段观察窗均值，以下峰值、段分类和前后统计都是事后描述。禁止把最终峰值、事后持续时间或未来窗口用于声称可在线实施的判据；禁止把高服务段命名为 request 初始扇出或“真过载”。1ms 桶不能推出亚毫秒精度。

四、必须补齐的表：有分母、面积、背景和时间关系
14. 背景表：逐池、逐桶宽打印 mu、最忙 10% 桶服务占比；对 m=2/4 打印高桶时间占比、高桶服务占比、非高桶均值/p50/p90/p99、非高桶总服务占比。非高部分不是某类请求的尾部。再打印连续非高区间长度 p50/p95/max，并单列左右删失段数；零服务池或空集合给 unavailable。
15. 集中段联合表：对起止均可见的高服务段，记录 duration_ms、peak_CPU_equiv、area_CPU_ms=sum(S×bin_ms)、excess_CPU_ms=sum((S-mu×m)×bin_ms)。报告完整段数、删失数，以及时长 [0,2]/(2,5]/(5,20]/(20,+inf)ms 四组的 count、总时长、总面积、峰值 p50/p95；这些是描述分组，未证明 2/5/20ms 是调度阈值。另列删失段的已观察面积，禁止悄悄丢失其服务总量。
16. 间隔/复发表：逐池、逐 m，完整段之间计算 gap=下一段开始-上一段结束，start_gap=下一段开始-上一段开始。报告可配对数与 gap/start_gap 的 p50/p90/p99/max，以及 gap<=1/5/10/30/100ms 的分子/分母。边界外未知下一段不算“没有复发”。不要称该间隔为请求到达间隔。
17. 前后背景表：分别以完整段“开始”和“结束”为锚，对每个 h=1/5/10/30/100ms，统计 [t-h,t)、[t,t+h) 的本池 S 均值及其他所有映射池的 S 之和的均值，同时给 W（若可用）。先积分求每个事件窗口均值，再跨事件报告 p50/p90；不拿分位数相减当因果效果。bin_ms>h 时 unavailable，不插值制造精度。
18. 每个前后格必须附总候选数、边界不足数、有效数，以及窗口内出现“本锚段之外另一高服务段”的窗口数；开始后的窗口包含本段、结束前的窗口包含本段，这是预期而非污染。另列不同事件窗口相互重叠的事件数，并说明同一 CPU 面积可被多个上下文窗口重复计入。主表保留全部可评价窗口；可再给无其他高段的子集，但必须附支持数，不把筛除复发后的子集代表全部。以上用于描述背景与再起伏，不用于证明旧请求与新请求的因果干扰。
19. 同期服务表：源池高服务时，打印其他池服务总和及 W 总和的 p50/p90/p99、同时高服务池数的计数分布；同时给源池非高时的对应值。始终先逐共同桶相加再取峰值/分位，禁止相加各池独立最大值。其他池低服务不等于 idle，不据此计算目标同 NUMA 可借资源。
20. 1/5/10ms、2/4 倍阈值均做敏感性，但不把它们当独立重复实验。仅有一段 10s 历史记录，事件和相邻桶相关，按池/按时间子段结果不稳定就明确写出。分位使用 nearest-rank 并附样本数；小样本 p99 应注明近似最大值，不伪造置信区间。

五、有限输出、核对与解释
21. 最终 <=100 行：输入/质量 <=12 行；1ms 主表 <=40 行；5/10ms 与阈值敏感性 <=15 行；少量真实时间片段 <=18 行；结论和不可得项 <=15 行。长表可保存在本机新文件，终端只打印路径/哈希。字段名与单位必须在表头清楚，不用“长工作/短工作低密度”替代数值。
22. 只选择三个可复现的展示片段：在 1ms、m=2 的全部完整段中，按 (area_CPU_ms,开始时间,池名) 排序取 nearest-rank p50、p95、最大者，重复则去重。每个打印池、绝对开始/结束、duration/peak/area，及开始前30ms、本段、结束后30ms 的本池/其他池平均服务和有效时间；边界不足按实际可见长度报告且标删失。这些样例仅用于检查形状，不代替总体分布，也不以人为挑选最好看的片段支持结论。
23. 做面积守恒核对：高+非高服务面积=全窗面积；完整段+删失段的已观察面积=高桶面积；合并桶前后总面积在相同时间范围一致。列源 audit 的缺失/删失数，不把完整行数当采集完整性证明。
24. 最后按“可观察事实 → 约束哪一种模拟现象 → 仍不能确定什么”给最多五条结论。例如：持续背景显著且脉冲复发频繁，可以要求场景族覆盖持续背景叠加反复释放；但不能据此指定背景来自哪个请求、80个算子后应接4个还是其他数量。若事实不支持该现象，就不能把它写成必须复现的真实特征。
25. 本次不推导请求 CPU 预算、不把 wake 周期当算子时长、不恢复 DAG、不从旧四池计算六 cluster 最优策略。报告应明确哪些后续模型维度受数据约束，哪些仍只能做有标注的机制敏感性实验。仅在之后的带 request/phase 标记 demo 中，才可验证“旧请求尚在执行时，新扇出竞争资源”的归属；这次历史补证不冒充该验证。
```

解释边界：补证的结果可以约束合成模型应保留的池级时间现象，不能唯一确定真实请求图。先前通用分析提示词及历史结论继续保留；本提示词新增的是背景、间隔、集中段面积与前后同期关系，不要求为复现旧数字反复扫描 trace。
