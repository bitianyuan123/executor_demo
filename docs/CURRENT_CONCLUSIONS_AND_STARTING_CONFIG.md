## 1. 负载模型：已测机制与尚未覆盖的业务关系

主线为每个选定且核实的硬件cluster一个Folly子池，业务持有一个高层总池。当前测试资源有六个cluster，NUMA0/2，每cluster含16个逻辑CPU；六池是资源选择结果，历史四池只是trace采集条件。

模型将业务拆成三个独立层次：

1. request到达：regular/入口burst、到达密度与并发在途分开；以计划到达时刻计请求时延，保留投递lag、失败及窗口后完成。
2. request内部：开始宽扇出，分支串行依赖，波间join，再产生后续fork。迭代/访问次数在策略间固定，task/request级计算量扰动可配置。后继真实消费前驱修改的分支数据，不以额外sleep假装cache损失。
3. 外部等待：D0直接推进；A0通过外部完成源但配置等待为0；A1增加固定到期等待。算子返回释放worker，完成后重新提交轻量恢复callback，再推进图；等待中的事件不计入CPU池ready工作。

已测机制包括regular/burst8、request/task异质性、branch-rw依赖、16/128 worker、每算子基准300万/37.5万迭代及10万/1.25万访问、12/96 QPS、D0/A0/A1及观测开关。阶段3还覆盖保持同CPU并集的none/numa/cluster部署。各批只回答其受控问题，不把不同批次拼成同一轮因果对照。

4020冻结合同：96QPS、1920请求；widths=80,4，depths=2,2，共168个业务operator与3个原控制callback；branch64KiB、shared0；迭代375000、访问12500、task级±25%及约1/8四倍工作；50%选中位置增加2ms等待，align0、源容量4096。各池16线程，RR/all/parent，仅同NUMA借出。这里96QPS和约1ms业务callback是受控工作族，不是由历史trace的0.85ms推算的生产标定。

没有覆盖任意生产DAG回放、多父大数据融合、共享写争用、真实网络/重试/超时分布和持续饱和验收。同步阻塞、集中异步恢复有实现/功能覆盖，不能写成它们已完成目标性能对照。绑定CPU也不保证数据页固定驻留本NUMA，尚未从硬件cache miss证明局部性收益。

## 2. 负载观测：Q保留，O作为候选，CPU作为慢反馈

| 信号 | 观测对象 | 获取/维护成本及用途 |
|---|---|---|
| Q | 所用Folly队列接口报告的未领取工作代理；可能基于共享permit | 原生近似O(1)读取，无新增统计写入；最便宜的基线，不覆盖所有已领取/运行工作 |
| I | callback开始后尚未返回的占用 | 少量原子读，开始/结束维护；包含抢占和同步阻塞，不是on-CPU或runnable |
| O | 包装器已预留/接纳而未完成的callback，失败提交回滚 | 生命周期计数，读O(1)；覆盖Q之外窗口，不含未ready图节点或已经detach的外部等待 |
| R | 已选池、尚未逐个交接到底层的批内预留 | 防止后续选择完全看不到本批；与O交接可短暂重复，不是事务快照 |
| CPU及runqueue等待增量 | 一段时间内取得的服务与可运行等待 | 后台按TID采集，热路径只读缓存；采集O(worker数)，标明时窗/年龄/有效性，不追随每个微突发 |
| request在途、source pending | 生命周期和外部等待 | 辅助定位准入/下游问题，不能直接加到O里当CPU需求 |

本版本Folly常规CPU任务先入队再通知消费者，精准唤醒并不意味着闭包绕过队列直接交给某线程。具体queue size是否覆盖通知后尚未运行的窗口取决于信号量实现，不能混用经典LifoSem与默认ThrottledLifoSem的语义。已活跃worker与被唤醒worker可继续竞争领取工作。详见[源码报告](../stages/02-folly/README.md)。

建议保留Q及可替换的I/O后端，不把“Q有盲区”写成“Q无效”。Q=0时可能已经有很多领取后的任务或即将到来的同批工作；I/O高也可能只是阻塞。历史unique-onCPU、waking与CPU相关性不证明callback I能普遍代理CPU需求。

当前评分为queue=`(Q+R)/C`、active=`(Q+I+R)/C`、outstanding=`(O+R)/C`；不能再把O与I相加。O能覆盖更多生命周期窗口，因此可作为总池集成的候选起点，但没有测出它普遍优于Q/active。

实现成本须按实际路径描述：Q评分有只读queue的快路径；O评分当前通过`BusinessExecutor::readLoad()`读取多个relaxed计数及Q，并非已经专化成只读一次O。所有策略仍维护生命周期及O/I/work计数，trace0也不是无观测维护。Q/O比较、trace1/0比较均不能量化删去全部计数的收益。既有stock池的TaskObserver适配每callback增加两次relaxed RMW，另有调用开销；应在任务开始前安装并保证生命周期，不能随时附加后漏记开始事件。

允许统计误差不允许C++ data race；relaxed原子读与竞争性fetch_add成本不同。生产热路径不读/proc、不扫线程、不同步打印。CPU后台每轮扫描后默认等待50ms；实际样本窗口为相邻有效采样间隔，包含扫描的影响，通用评分类最大样本年龄默认100ms，demo CLI默认150ms。这些是已有实现参数，不能保证捕获1～3ms尖峰。无效/过期CPU样本回退O，不能把回退结果宣称CPU评分胜出。

低扰动日常输出可优先保留每秒请求成功/失败/拒绝、mean/p99、CPU/完成请求、各池Q/I/O的适量采样、借出及准入计数；周期采样可能漏掉短峰。需要解释问题时才短时开启细粒度记录，分别看业务operator、恢复callback、source lag及路由原因；全量trace不作为默认生产配置。新接入的汇总维护本身也须评估开销。

### 4025补证：支持细化门控，不支持直接定阈值

历史10秒服务序列中，1115个高服务段以S>2×本池全窗均值定义；≤2ms占55.61%事件却只占9.67%高段CPU服务面积，>5ms占25.29%事件却占74.70%面积。非高桶仍贡献各池38.679%–48.533%服务；高段间隔中位数11–15ms。它支持覆盖峰间服务、重复突发及低谷重置，不证明独立背景任务、request尾链或请求到达规律。历史四个未绑CPU池仍只是采集条件。

候选PressureGate独立于LoadScorer与ContinuationPolicy：以当前压力做严重旁路和快停止，有效采样状态做中等压力持续确认；同NUMA合格目标、当前负载/预留及收益仍须检查。裸O/C可作首版持续计时候选，但含抢占/阻塞，非runnable；(O+R)/C交接时可能重复，不是精确N。生产默认、现有high=1与parent策略不变。实验初值M=1、L=.75、D=0/1ms，后续单独比较H关闭/2及D=.5/3ms，仅为待实现方案的探索梯度，不是当前可执行CLI或生产推荐。详见4025的采样代际、目标前瞻和匹配基线设计。

### 4026补证：同池相遇成立，目标保护成为具体干预问题

已有六轮3M tail4离线CSV分析：home同池相遇为0/192新请求，Q/O均为128/192；所有策略同NUMA相遇仍为128/192，说明同NUMA与同池必须区分。后期等待与更新首波同池相交的callback只占Q的3.95%–4.09%、O的4.30%–4.39%，却覆盖各自95.31%–95.32%、96.89%–96.94%的后期等待。相遇组完整等待均值Q为3.42–3.53ms、O为2.59–2.68ms，存在长度偏差，不能把组差当迁移因果成本。

分母是每请求88个后波业务callback，包含4个后波stage0与84个普通后继；不是仅普通后继的分母。执行区间是callback墙钟占用，不是on-CPU；交集求和单位是callback-ms，不是请求关键路径。128/192受规则12QPS、RR及三个相邻home同NUMA影响，不能外推为生产概率。

## 4. 算法与工程归属

业务只持有总池及必要的request上下文：`beginRequest`确定home，普通add、fork批量提交和外部continuation复用总池投递路径。内部明确L1/L2语义；普通add不能自行推断多父数据归属、fork范围或跨RPC生命周期。

1. L1用已有RR或颜色hash确定固定request home。本阶段不改为依赖请求时延反馈的LALB。
2. L2只在新ready callback提交时决定位置，有parent则优先实际父池，否则home；每分支独立保留上下文，不共享一个不断改写的request当前池。
3. 当前count候选以`(O+R)/C`评分。偏好池score**严格大于**high才搜索；候选必须严格更轻，且改善**严格大于**min-gain，平手留下。候选不必低于high，因此“较轻”不等于idle。现在可独立启用target-limit，要求目标(O+R+B)/C不超过配置比值；默认0关闭，仍非硬容量保证。
4. 先搜索同NUMA其他cluster；只有同域没有合格改善且开关允许时才搜索远端并加罚项。不是无条件全机argmin；跨域罚项与score单位一致。
5. parent跟随后续实际来源；ReturnHome为独立规则，home评分≤return-low时可优先回去。它不要求home比parent更空闲，也不是普通借出的gain判断。启用target-limit后回home也接受同一目标准入；失败后继续原preferred的判定。parent仍可因普通选池回home。
6. hop限制沿上下文路径的累计改池次数，chunk让一组callback共用一次选择/预留，但它们仍逐个入队。并发选择与预留非事务，不能保证零争抢、完美均衡或公平。

当前是提交时放置，不搬运已入队任务、不抢占运行算子、不接管内核runq；没有实现后台工作窃取、P2C或持续压力状态机。算法借鉴拓扑分层和迁移抑制，不需要复刻内核调度器。

先使用高层组件和stock Folly公共接口。第五阶段仍负责接口归属和生产集成，但目前没有必须修改Folly核心的证据；已有可选库扩展也不等于所有高层/Future/KeepAlive接口已验收。真实接入仍需核实异步所有权、取消、异常、部分提交和shutdown/drain。

## 6. 什么情况下才再收集或实验

| 新的明确决策/证据 | 对应必要补证 |
|---|---|
| 要声明稳定、可发布的mean/p99改善 | 冻结合同，独立交错整轮与留出工作seed；预先定义CPU/时延/失败门槛及预算，补齐v3跨轮严格配对分析 |
| 当地大量同步阻塞，或quota/外部CPU竞争 | 分别验证worker预算、Q/I/O状态含义与容量；低CPU不表示可接纳工作 |
| 集中RPC完成、源延迟主导，或callback远短于当前约1ms | 单轴恢复形态/观测维护/控制callback占比实验，先验证实有该机制 |
| 准备启用跨NUMA或更大共享数据 | 核对页位置和CPU资源，再做同工作跨域对照及CPU/请求核算 |
| 要承诺持续过载下进展、公平或准入行为 | 专门设计无闲池/持续需求合同；已测peak-inflight约2–4不能替代饱和验收 |
| 发现短峰导致无效迁移、希望加入持续压力门控 | 先证实该反例，定义状态机、下降复位、采样空洞和仍有新ready可路由的机会，再实现并验证 |

上述生产调优项仍不自动展开；历史trace定向摘要、原矩阵离线补齐、三份CPU恢复和4026阶段联合分析均已完成，无需再采同一证据。4027目标干预及4028尾部补查也已完成，本轮到此收束；源持续门控是未实现的独立问题，不自动叠加。复杂依赖、生产阶段形状与持续饱和需按各自决策验证，不能只看算子数和总在途。保存原始CSV/metadata/构建标识，终端回传摘要即可。生产环境的agent仍按提示词A只读核实，再进行可回退集成和功能验收；当前分析不依赖生产访问。
