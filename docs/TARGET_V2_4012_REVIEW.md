# 4012 计数信号与线程数量对照结论

**当前状态：4017已完成六轮既有CSV的到达核查，见[结论](TARGET_V2_4017_REVIEW.md)。不再重跑CPU矩阵、到达诊断或追加trace/阈值。异步完成源与驱动已加入工程，当前按[异步功能指南](TARGET_V2_ASYNC_FUNCTIONAL_GUIDE.md)进行编译及小规模功能验收；等待期间释放worker，恢复callback再推进图。性能对照待功能验收后另立合同。目标始终每个已核实硬件cluster一个池。** 下文保留当时证据/命令，不是新的执行清单。

本批24轮完成。对固定的burst8、分支读写CPU工作族，**较少worker带来的均值改善比Q、Q+I、O之间的差异更明显**；两档线程数均支持在压力下借用同NUMA池。保留16线程与Q作为后续简化候选，但没有据此确定生产线程数、最优评分或稳定p99。

下一步只做[6轮机制诊断](TARGET_V2_SIGNAL_DIAG_GUIDE.md)，解释线程档变化时的队列盲区与实际借出。运行实现、负载、阈值和Folly保持不变；不再重跑24轮信号初筛，不要求继续扫描旧trace或访问真实业务。

## 1. 实验完整性与可比范围

证据为用户提供的4012.log终端文本，SHA256为`ed97d0170150152f0f8f6efd74100fc3c2d87427956cfc4017411aaa35a2c9a5`。审阅结合仓库实现和[预先实验合同](TARGET_V2_SIGNAL_THREAD_GUIDE.md)；[机器可读摘录](../results/review/4012_summary.json)保留打印精度，不替代目标机原始CSV。

- 24条实际命令、24份cohort表、24份flow报告和18组同线程home配对齐全。命令仅policy、threads、seed、output变化，每seed八格一起打乱。
- 所选六个已核实硬件cluster各一个池，NUMA为0/2；每池16或128线程，两档名义容量均为16个逻辑CPU。总worker为96或768，CPU并集不变。名义容量不等于16个物理核或已校准吞吐容量。
- L1为RR home；L2为all-parent、chunk1、hop4、仅同NUMA，count评分默认high1/low0.5/gain0。parent下low不承担主动回home功能。
- 每轮240/240完成，拒绝/失败0，peak-inflight均8；正式计划到达窗口`[2,18)`各192/192完成、24个完整burst，无边界/末尾不完整burst。
- 各seed八格打印的工作签名、固定工作签名、总迭代/访问数、arrival hash及checksum一致。我们没有取得原CSV重新做逐请求复算；不同线程档的差是有意改变worker预算，不属于资源完全相同的策略配对。
- 实际attempt跨度均值0.689～0.701ms，单轮最大值0.695～0.886ms；最大值出现在421/128/queue。计划跨度为0.700ms，整轮attempt lag p99为0.058～0.077ms。保留这些波动，不沿用4011更窄的范围，也不把attempt当全部算子ready时刻。

固定负载仍为12QPS、每批8请求间隔100µs、宽80/4、深2/2、每分支64KiB读写、task级±25%及约1/8四倍工作。每request含168算子和3个控制callback；没有异步RPC或同步sleep。三个seed改变工作分布，每格只运行一次，不是固定工作三次重复。

以下全部采用正式cohort的request mean / p99，单位ms，不混用运行前段打印的整轮时延摘要：

| 420 | 128 | 156.996 / 222.325 | 149.529 / 192.494 | 148.903 / 189.719 | 149.233 / 198.529 |

三种评分均包含路由预留R并除以C：`queue=(Q+R)/C`、`active=(Q+I+R)/C`、`outstanding=(O+R)/C`。active不是仅I。

每个范围是该档三个seed、三种信号各自相对同期home的结果，并非把分位数合并计算。借出降低request时延，同时CPU/请求略增；不能把收益解释为CPU消耗或cache miss减少。

### 同策略从128减至16线程

下表正值为均值下降比例，以128线程为分母：

| 策略 | seed420 | seed421 | seed422 |
|---|---:|---:|---:|
| home | 1.120% | 1.192% | 1.490% |
| Q | 3.983% | 2.927% | 3.636% |
| active | 3.622% | 3.119% | 3.269% |
| O | 3.783% | 3.917% | 4.032% |

12对整轮CPU/请求也均小降0.066%～0.244%。**线程预算值得优先作为独立优化轴。** 但尚不能归因于内核runq、调度次数或缓存，因为trace0没有对应观测，线程数也会改变就绪队列、选池时序及后继释放。

p99不是全面改善：420/home从222.325升至224.039ms，420/active从189.719升至190.349ms；其余十对下降。每格192个样本的nearest-rank p99是第二大值，且来自24个相关burst，不能作为正式尾部验收。

### 三种计数信号没有分出稳定赢家

| 每池线程 | seed420均值最大差 | seed421均值最大差 | seed422均值最大差 |
|---|---:|---:|---:|
| 16 | 0.078ms | 0.587ms | 0.432ms |
| 128 | 0.626ms | 1.193ms | 0.747ms |

最大差相对同格最低均值均小于0.8%。128线程active三seed均值最低，但相对Q只低约0.088%～0.419%，且421的p99比Q高2.186ms。16线程O相对Q的均值差为+0.015/−0.587/−0.008ms；128线程为−0.296/+0.940/+0.614ms。

因此不宣布O优于Q，不宣布active最优，也不宣布三者等价。本批只有共同默认阈值的一次净路由收益对照，并非分别充分调参后的比较或计数准确率测试。总池在queue/home下也维护部分生命周期计数，本批没有测得删掉I/O维护后原生Q方案的完整成本优势。

## 3. 对负载观测与真实业务的阶段指导

Q在128线程下仍改善均值4.76%～5.53%，所以“worker过配后Q必然失效”过强；“Q在所有场景都足够”同样没有依据。大批提交期间Q仍可能暴露积压，而任务被领取后的CPU竞争或阻塞可能落到Q之外；具体在本合同中怎样发生，需要单独诊断。

阶段3已经研究条件负载与task等待的关系，4012补充的是**改变评分和线程预算后整request时延怎样变化**。二者不是统一的“队列长度→request p99”公式。本轮trace0不能提供Q/I/O的条件分桶，不能推算Q变小多少、等待转移多少或负载预测准确率。

可交给真实环境agent的原则是：先核实同步阻塞/异步释放worker与callback边界，把线程数和评分作为两个独立轴；CPU占主导时优先纳入接近名义CPU数的worker候选，保留Q低成本基线和I/O补充选项。**16仅是本CPU子集的一档，不是生产默认值**；存在同步阻塞时较少worker可能限制进展，异步RPC也不能用占线程sleep代替。

12QPS相同不代表总压力匹配。本批整轮CPU/请求约1.34～1.37秒，按12QPS换算的名义需求约16.1～16.4个逻辑CPU的CPU秒/秒，即所选96逻辑CPU预算的约17%；这是需求换算，不是实测利用率，也未复现原描述的全应用约50%CPU。不能通过人为凑平均利用率替代真实算子、依赖、到达与阻塞关系的校准。

主线仍为每硬件cluster一个子池、一个业务总池、L1 request home和L2新ready算子调度。先同NUMA，跨NUMA、fork/all和parent/home继续作为独立候选。当前结果没有新增修改Folly核心或引入3ms门控的必要性。

## 4. 本轮工程决定与下一步

1. 冻结4012结果，更新当前入口、生产手册及纯prompt交接中的证据。运行代码、负载和阈值不变，无需重编。
2. 下一批只有6轮：home/Q/O × 16/128，固定seed421，trace1，其他合同不变。保留home以查看未经L2改变位置的原池压力；暂不重复active的小幅排名。详见[命令和预先判据](TARGET_V2_SIGNAL_DIAG_GUIDE.md)。
3. 该批只解释机制，不把trace1与4012拼成性能重复，不以其小样本p99决定赢家。之后依据发现选择一项：固定合同交错重复、regular守护或同步阻塞边界；不自动追加全部矩阵。
4. 旧trace无法识别的业务到达、算子身份、RPC和数据关系保持unknown。生产代表性、正式尾部与生产接入仍待当地验证；可以用[纯prompt方案](PRODUCTION_AGENT_PROMPTS_ONLY.md)独立推进，不要求传文件或跨环境连接。

本地验证范围：终端24格字段/合同与算术复核；新指南命令语法和六格计划核对；相对链接与纯prompt独立性检查。没有在开发机运行ARM性能，也没有因文档更新重复编译或启动压力测试。
