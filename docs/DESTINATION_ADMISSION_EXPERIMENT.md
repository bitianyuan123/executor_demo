# 借出目标余量：候选设计与有限对照合同

**目标借入保护现已实现为默认关闭的可选策略；尚无目标机性能验收，不是生产推荐。** 实际编译、功能验证及有限矩阵入口见[执行指南](DESTINATION_ADMISSION_RUN_GUIDE.md)。源池持续门控仍未实现。 4026补齐了原六轮任务CSV的阶段关联；不要求为本页重跑现有矩阵、补采trace或访问真实业务。当前默认策略、负载图和参数保持不变。下一项实验优先验证目标余量，再在相同目标规则上验证源池持续压力门控，避免将两者收益混算。

主线始终是每个已核实的硬件cluster一个子池，业务只使用总池及request上下文。历史四个未绑CPU池只提供旧trace的观察条件，不决定本设计的池数、CPU划分或负载缩放。

## 1. 为什么先验证目标保护

[4024](TARGET_V2_4024_REVIEW.md)的3M深链图中，Q/O降低首波等待和请求整体时延，却提高了后波等待。4026沿实际chosen池关联后，home两轮没有新首波与旧后波的同池相遇，Q/O各有128/192个新请求相遇；Q约95.3%、O约96.9%的后波callback等待时长与更新请求首波的执行区间重叠。

这支持“借出目标中原有工作的等待需要纳入策略评价”，不证明这些等待全部由新首波造成。执行区间是callback墙钟占用，包含抢占；等待是选池后的submitted至start，不是精确Folly Q或内核runq。暴露组更容易包含长等待，不能将其均值差当作因果效果。

源池多等一段时间，可能减少无收益迁移；也可能在门控打开后仍向同一目标送入大量工作。目标余量解决的是“允许借出之后能送到哪里、送多少”。两项机制应单独对照。当前数据没有证明绝对余量上限必然更优：保留余量也会减少可借资源、使源池排队更久。

## 2. 与当前实现的边界

当前`RequestExecutor`先比较源池分数与busyHigh，再寻找分数更低且收益超过minGain的同NUMA池；有开启跨NUMA且没有本地改投时，才搜索远端。4026分析时已有R预留和逐chunk选择，没有目标投递后保护；本次增加独立AdmissionPolicy过滤，持续压力状态机仍未实现。

| 当前机制 | 已有能力 | 不能替代的能力 |
|---|---|---|
| busyHigh | 源池达到何种分数才寻找其他池 | 目标还能接纳多少 |
| minGain | 要求相对分数改善 | 目标绝对余量或已有请求进度保障 |
| batchChunk | 控制一次选择后投递的批量 | 自动把整个批量计入目标上限 |
| R预留 | 后续观察可看到尚未交接的工作 | 跨发送方原子分配或严格不超配 |
| parent / return-home | 子任务沿实际落池续接，或满足条件时回home | CPU抢占、优先调度或强制旧请求公平性 |
| fork-only | 普通后继不再尝试换池 | 防止新首波借入正在执行旧后波的池 |

目标余量不移动已入队任务，不抢占正在执行的算子，不建立全局流控或业务拒绝机制。本候选只约束向其他池借入的新ready callback；没有合格目标时，继续投递preferred池，不阻塞调用方、不因本规则丢弃任务。已有关闭、容量拒绝、异常及取消处理合同仍保持并完整计数，不被此规则掩盖。

## 3. IPO与选择流程

业务继续调用现有总池`add`、`addBatch`及continuation接口；策略位于总池内部，业务不传池编号、不扫描CPU、不参与负载判断。

| 项目 | 合同 |
|---|---|
| 输入 | preferred池、request home与续接上下文、当前源分数、候选当前负载样本、当前R、本次将要投递的任务数B及工作估计、配置代际、拓扑、收益和跨NUMA规则 |
| 处理 | 源池资格判定 → 同NUMA候选有效性与投递后余量检查 → 在合格目标中按原分数/收益选池 → 无合格本地目标时，按开关检查远端 → 无目标则留preferred |
| 输出 | chosen池、主决策原因、是否借出、候选过滤摘要、选池时使用的压力口径与B；按既有流程发布预留并入队 |

```text
ready callback / 一小批ready callbacks
  → 得到preferred（通常为实际parent池）和批量B
  → 原pin-home / hop / fork等资格检查
  → 源是否允许借出？否：投preferred
  → 扫描同NUMA：有效样本 + 投递后上限 + minGain
  → 有合格目标：选择其中分数最低者
  → 无合格本地目标：按跨NUMA开关及收益规则扫描远端
  → 仍无合格目标：投preferred
  → 发布本次预留 → 入队 → 交接后释放预留
```

“同NUMA优先”应优先选择**合格**本地目标；一个很忙但比源略低的本地池，不应阻止检查已允许的远端目标。首轮实验仍关闭跨NUMA，避免同时改变资源范围。严重源压力的立即旁路只能绕过源持续确认，不能绕过目标有效性、余量或收益检查。

回home是另一个放置动作。首轮保持parent，避免混入回迁。实现已明确：启用目标准入时ReturnHome也检查目标，拒绝后继续原preferred决策；关闭时保持原回迁规则。首轮仍不混入return-home维度，不得借“恢复亲和”绕过新增保护。

## 4. 首个可实现的压力口径

第一版仅在当前即时O策略上增加可关闭的目标规则，保持源评分、收益和其他逻辑不变。O为包装器已接纳未完成callback，R为已发布但尚未完成交接的预留，C为显式配置的容量；C不是worker数，也不保证16个SMT逻辑CPU等价于16个物理核心吞吐。

候选目标投递后压力估计为：

```text
target_after = (O_snapshot + R_snapshot + B) / C
允许借入 = 样本有效 && target_after <= target_limit && 满足原收益规则
```

B必须是当前这一chunk的实际任务数，不能固定写1，也不能把整次request的剩余算子数都算进去。现已在选择前确定chunk大小，并将B传入选择及准入接口。上限关闭时回到原选择行为，不将“关闭”实现成很大的有限值。

此表达式是保守程度可能变化的**近似计数规则**，不能宣称严格容量上限：

- 交接时O已经增长而R尚未减少，两者可短暂重复计数。多个原子读数也不是一致事务快照；本轮先保留原O+R口径，观察拒选成本，不同时重做交接协议。
- 多个发送方可能同时读到余量、都选中同一池，然后才各自预留；投递后的真实O可能超过目标线。
- O包含已开始但被抢占、同步阻塞等callback；它不是当前CPU需求。数目相同的任务可能有完全不同的剩余工作。
- 不直接将同一比值套到work或CPU-hybrid分数上，它们的单位和时效不同。若未来分离“源评分器、目标准入器、目标排序器”，必须保留单位合同及各自有效性检查。

因此计数上限只用于路由决策。若未来确实需要严格的借入令牌或原子容量预留，应另立合同，定义原子获取、失败重试、回滚及开销；不能通过给近似读数改名实现硬保证。

对Q策略新增O目标检查会增加计数读取并改变决策输入；必须作为新组合记录，不能称为原Q策略的等价实现。第一轮不混入该组合。

## 5. 成本、诊断与并发验收

候选读取复用已有发布的原子计数。热路径不得执行/proc读取、系统调度采样、遍历worker、动态分配或等待后台采样线程。总池数小，扫描成本随池数而非线程数增长；新逻辑仍须测量每次提交CPU成本和整轮CPU/请求，不能仅凭“多几次读取”宣称无扰动。

建议主决策原因至少区分：源未触发、选中本地、选中远端、无合格目标而留本池。候选过滤摘要区分样本无效、投递后余量不足、收益不足。每次选择只产生一个主原因；候选过滤次数可大于选择次数，不能混用分母。保留B、选中目标投递前后的估计及计数口径，trace关闭仍应有可解释的轻量汇总；计数实现本身需避免引入新的共享热点。

首轮必须覆盖：

1. 关闭时路由与原策略一致；恰好达到上限可选，超过上限不可选；非整数C和B>1按合同处理。
2. 本地池只有相对更低但没有余量时不得判合格；若跨NUMA开启且远端合格可继续选择；全部不合格回preferred。
3. 无效样本不视为空闲；当前任务数、批量与计数运算不溢出。
4. 多发送方同时选池、预留交接、入队拒绝和异常回滚不丢任务、不重复执行、不泄漏预留；允许的近似超配需可观察，不能用测试通过宣称不存在竞争。
5. pin-home、hop、fork-only、drain、continuation生命周期合同保持；新增路由规则不向业务暴露池编号。
6. 后续严重旁路不能越过目标拒选；目标规则关闭/开启的配置被完整记录。

目标余量可能为后继留下执行机会，但没有调度优先级或请求级公平性保证。preferred池的新home任务、正在执行的长算子和未来异步恢复仍会占用资源，不能承诺“保留4个位置就保障4条链”。

本节为固定实验合同，现有`--target-limit`与专用矩阵脚本已实现。请先按[执行指南](DESTINATION_ADMISSION_RUN_GUIDE.md)完成当地功能验收再运行；工具生成参数、新输出目录和构建标识，拒绝覆盖旧结果。默认关闭为0，两个正比值为1.0及0.75。

1.0与0.75仅表示本试验中分别约16和12个计数位置的探索值，不是生产容量认证或推荐阈值。固定工作相等不等于不同图的实际CPU时间相等。两个seed的短试验用于筛查机制和方向，不作稳定p99验收；当前192请求cohort的p99依赖极少数尾部请求。

每轮同时报告请求mean/p95/p99、CPU/完成请求、首波和后波等待分布、改投/回迁、失败/拒绝/到达lag、目标准入原因以及阶段相遇指标。阶段相遇使用与4026相同的定义，不将callback占用改称CPU利用率。若需要细粒度CPU服务，沿用既有采集工具作为单独的有开销实验，不把它设为本轮路由对照的前置条件。

不得只以降低后波等待或迁移率判优：如果效果来自几乎停止借出，同时请求整体明显变慢，需要如实呈现取舍。也不得只以整体mean更低忽略后波尾部及CPU成本。超过首轮后，仅对有明确收益/代价信号的配置扩大独立重复和尾部样本；由业务SLO与资源预算给定接受范围，不从现有两seed倒推阈值。

若余量机制在3M两图得到可解释结果，可再复用46875档图A作小工作成本反例，保持原工作参数及工作指纹，不开展完整三档笛卡尔积。失败、指标异常或效果接近测量波动时先查原因，不能通过不断增大扇出追求明显收益。

## 7. 与源池持续门控如何衔接

目标规则应先有独立即时组。然后选定同一目标规则，将源持续门控D=0与D=1ms配对；仅采样但不开门控作为开销组。源信号、M、释放线、目标规则、续接和NUMA范围全部一致。若从当前O+R改为裸O，必须先建立该新口径的D=0组，不能直接归因于等待时间。

严重旁路H先关闭；确认普通持续路径有实际影响的ready提交后，再单独比较H=2.0这一探索点。无论H如何，目标准入仍执行。必须报告持续确认、严重旁路、压力释放、过期回退和无目标各路径覆盖的任务数。

80项一次投完后，D毫秒才打开门控不会自动搬走已入队任务；若几乎所有提交都走严重旁路，则也测不到D的价值。不能只看到两个配置时延接近就称时间门控无用；应先确认其作用对象。采样连续性、低谷重置、代际失效与时钟成本沿用[4025门控合同](TARGET_V2_4025_REVIEW.md)，不是本次目标余量实现的隐含组成部分。

## 8. 后续适用范围

当前3M同步计算、T16结果只验证这一资源与工作合同。生产可能每池线程远多于16，Q很低但许多callback已领取、在内核排队；此时O目标规则比单独Q覆盖更多已接纳工作，却仍可能把同步阻塞误当CPU压力。异步悬挂期间通常不在O内，未来大量恢复也不在当前目标快照中。线程过配、同步等待和异步集中恢复需用已有独立负载族另做反例，不能据本轮直接选生产线程数或阈值。

既有两图保留链式数据依赖和整波join，尚无任意局部join或多父融合；它们可以检验路由机制，不代表完整真实DAG。4025的服务复发与峰间服务可以指导将来的覆盖维度，但不能唯一确定每算子耗时、图宽深或请求周期。

工程推进终点是可关闭、可观测、业务无池感知的候选策略，以及固定工作下的可复核取舍。是否进入生产当地调优，应由当地实现和SLO检验，不依据历史四池trace直接指定新架构的参数。
