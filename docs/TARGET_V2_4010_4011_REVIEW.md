# 4010/4011阶段结论：结束旧trace补证，转入计数信号与线程对照

本文安排的24轮信号/线程实验及后续机制诊断已由4012/4013完成，9轮regular守护也已由[4014](TARGET_V2_4014_REVIEW.md)完成。当前仅执行[短工作S四轮](TARGET_V2_SHORT_WORK_GUIDE.md)；本文保留当时证据与决策。

## 1. 结论与当前决策

**可以给出架构与实验方法上的指导，尚不能指定生产最优线程数、繁忙阈值或唯一调度策略。** 现阶段更支持“cluster内保持亲和，压力下允许同NUMA借出”的可配置方案，而不是把每个request永远锁在一个cluster。它仍须与同资源的none/numa/home配置在真实业务上比较；目标架构不是已经证明的全局最优。

本轮决策：

1. 4010的有界离线审计完成。旧trace没有request/operator/RPC标记，不能继续靠扫描补出业务模型。外部新增解析器还存在状态/分桶缺陷，细节见[源码审计](../results/review/TRACE_4010_PARSER_AUDIT.md)。不再把修复并重扫旧trace设为下一步前提。
2. 4011的18轮观测对照完成。关闭详细trace后，all相对fork的均值优势仍在，但较小，p99方向不稳定；保留两种策略，正式性能比较优先trace0，trace1用于独立诊断。
3. 固定已有合成负载，不把0.85ms当算子耗时，不引入固定3ms门控，不根据历史四池峰值拟合六cluster。下一批为[Q/active/O × 16/128线程对照](TARGET_V2_SIGNAL_THREAD_GUIDE.md)。
4. 生产环境可由当地agent独立探索代码、指标与资源，然后在明确范围内调优。采用[分阶段生产agent手册](PRODUCTION_AGENT_PLAYBOOK.md)，给**候选初值、量纲、有限梯度和停止规则**，不下发未经当地验证的“最优参数”。

主线保持：所选硬件cluster各一个子池，上层一个总池；L1确定request home，L2选择新ready算子的执行池。同NUMA优先，跨NUMA独立验证；parent/home、fork/all为策略维度。历史四池未绑CPU仅是证据来源；当前测试用六池是该CPU子集的拓扑结果，不是库内常量。

## 2. 证据与实验合同

本报告审阅用户终端文本和仓库实现，未取得目标机原始CSV，也没有在开发机代跑ARM性能。机器可读摘录见[4011摘要](../results/review/4011_summary.json)；它保留打印精度，不冒充原始样本。

- 4010.log SHA256：`107e1de3cf26b4007b6e32529140dec2d207fcf3d52410c2e6cb661a9bf08984`，是分析环境对历史trace的外部脚本、JSON、报告。
- 4011.log SHA256：`70ab795bd6088682d655ce1c8f9f599b05d8a31742826ec57260ecf74519153d`，是独立ARM测试环境的18轮home/fork-parent/all-parent × trace0/1 × seed420/421/422。
- 目标实验均为6个cluster、每池128线程、名义capacity16、NUMA 0/2、同NUMA借出；burst8、12QPS、branch-rw 64KiB、task级长短扰动、宽80/4、深2/2。工作参数延续4009，未生成异步RPC。
- 全部18轮240/240完成，失败/拒绝0；计划窗口`[2,18)`各192请求、24个完整burst，peak-inflight均8。每seed合同、逐请求checksum及trace开关比较通过目标端脚本审计。
- 实际批内attempt跨度均值0.693～0.696ms、最大值0.695～0.698ms，计划跨度0.700ms；整轮attempt lag p99为0.058～0.063ms。attempt在request构造/root提交之前，不能当作全部算子同时ready的时间。
- trace1每格32832个callback；trace0不采任务级等待/CPU/迁移，不能将其默认零值解释为没有迁移。

每格只有192请求/24个相关burst，每seed仅一次。不同seed改变确定性任务工作分布，不是同工作三次独立重复；没有置信区间，p99是小样本描述。

## 3. 4011：均值方向保留，尾部和收益幅度尚不稳定

| 420 | 1 | 158.781 / 224.678 | 150.573 / 197.389 | 149.278 / 190.822 |
| 421 | 0 | 159.173 / 226.813 | 152.308 / 209.136 | 150.408 / 202.228 |
| 421 | 1 | 160.111 / 225.258 | 152.574 / 200.537 | 150.585 / 201.001 |

trace0下，fork相对home均值改善4.31%～5.21%，all改善5.07%～5.74%；all相对fork改善0.55%～1.25%。**“借出优于硬锁home”在这批场景继续成立；all的均值优势不完全由开启详细trace造成。**

但不能升级为“all总是更好”：trace0的seed422，all样本p99比fork高2.848ms；trace1的seed421也高0.464ms。4008 regular下all/fork均值本就接近且方向不一。应保留fork作为更少后继选池/迁移的候选，后续按业务目标与独立重复选型，不能只盯均值。

| seed | all−fork mean，trace0 ms | all−fork mean，trace1 ms | 两者差：trace1−trace0 ms |
|---|---:|---:|---:|
| 420 | −0.893 | −1.295 | −0.402 |
| 421 | −1.900 | −1.989 | −0.089 |
| 422 | −0.836 | −2.206 | −1.370 |

最后一列描述观测开关与策略差的交互。尤其seed422，变化已与原约1%的候选收益同量级，因此不能说“trace成本小，所以排名不受影响”。这也不把差中差全部归因于追踪：每格只有一次、顺序/系统波动和调度反馈仍在。数值采用报告内部精度的差，显示均值相减可能有0.001ms舍入差。

## 4. 4011：详细trace有可见CPU成本，不能称全部观测开销

trace1−trace0的整轮运行阶段CPU/完成请求差：

| 策略 | seed420，ms / % | seed421，ms / % | seed422，ms / % |
|---|---:|---:|---:|
| home | +8.893 / +0.659% | +9.923 / +0.726% | +8.239 / +0.608% |
| fork-parent | +5.242 / +0.387% | +6.784 / +0.495% | +6.566 / +0.484% |
| all-parent | +4.645 / +0.343% | +4.874 / +0.355% | +7.939 / +0.585% |

九个对照CPU差均为正，约0.34%～0.73%。这是该固定负载下的端到端观测敏感性，包含调度/内存间接影响；不能外推为短算子或生产上的固定比例。request均值开关差也不是统一固定税：home为+0.493%～+0.927%，fork为+0.175%～+1.543%，all为−0.041%～+0.638%。

CPU分母是整轮240完成请求，时延cohort是192请求；不能用二者相减拆解时延。CPU计时不含建池/trace数组预分配及事后CSV导出。trace0仍维护Q/I/O、预留、生命周期和request统计，本轮没有测得“整个总池/所有负载观测”相对原始Folly的完整成本。

工程选择：性能矩阵先trace0、保持必要路由计数；需要解释特定异常时再做小批trace1配对诊断。生产观测优先复用已有指标或抽样完整request，维护成本与读取成本分别测；不因上述比例就默认全量逐算子CPU计时可长期打开。

## 5. 4010：哪些能保留，哪些必须降级

外部报告正确指出：旧五类sched事件无法恢复业务到达、每request算子/DAG、CPU/request、RPC或数据first-touch。原1266段、N(t)定义与EWMA模拟产物未找到，**3ms、0.9C/0.75C/2C均未获验证**。没有依据要求当前demo改成0.85ms算子。

对其新增S3结果还需进一步降级：

- 88858个闭合线程周期、均值约868µs的结果，使“7.8 / 8900”与线程wake→sleep周期近似相容；这只是候选解释，不能称已经证明原分析的定义，更不能叫Folly任务CPU。
- 解析器跨过多个1ms桶时只更新起点所在桶，未将持续状态覆盖到后续桶；初始化也没有unknown覆盖状态。因此不能直接接受其“未知不补零”或10.6%～20.6%的超16桶占比为可靠阈值依据。
- 固定10.000000s过滤/积分，却部分速率用10.001075s作分母；影响约0.01075%，虽小仍应统一。报告将onCPU差异归因于窗口边缘未完成误差分解。
- 状态机对异常序列和边界的处理尚不足以保证精确runnable。具体反例及影响范围见[审计](../results/review/TRACE_4010_PARSER_AUDIT.md)。这不自动否定独立S1历史统计，也不估算这些缺陷对本份真实trace的实际偏差。

因此结束“继续从同一份旧trace挖出生产模型”的循环。后续如要使用S3桶数，先修状态机并用小型合成轨迹验收，再决定一次有界重算是否必要；当前计数信号实验和生产本地探索均不依赖它。外部报告中的“数十ns时钟”“8%～11%删失”也不能未经口径与目标机实测直接写入生产成本预算。

## 6. 累积阶段结论与生产含义

| 已有探索支持什么 | 对真实应用的指导 | 不能推出什么 |
|---|---|---|
| 阶段3：16线程集中负载下Q对等待预测很有信息；更多worker可缩队列却拉长callback墙钟 | 保留Q低成本基线，评价整request、CPU/请求和尾部；线程数是独立优化轴 | Q无用、Q=0一定空闲、或增加线程必然提速 |
| 不同CPU允许范围改变峰值可用并行度；cluster限制可能暴露扇出等待 | 在同CPU并集、池数、总worker预算下对比none/numa/cluster；不要只绑核后就宣告亲和失败/成功 | 当前硬件cluster一定等于最佳缓存域，或cluster亲和必然优于NUMA |
| v2 regular与burst收益差异很大，平均QPS解释不了瞬时竞争 | 保留孤立扇出与共同竞争场景；生产区分executor入口与请求内部ready突发 | 人工burst8已复刻真实到达，或应用整体50%CPU已复刻 |
| 同NUMA借出在当前合同下反复优于home；all额外收益小且依场景变化 | 实现总池门面、保留home/fork/all；先同NUMA，再测试跨NUMA与parent/home | 生产应默认all、必回home、必跨NUMA，或已证明缓存收益 |
| Q=0而I高、Q>0而I不高两类样本存在 | 比较Q、Q+I与O，结合线程档看净收益；注意定义和低扰动实现 | I就是kernel runnable，或O是精确剩余CPU工作 |
| 768 TID后台proc扫描曾完全回退O且增加CPU；4011详细trace也有成本 | 高成本内核计账用于低频诊断；热路径读缓存/计数，样本失效不当空闲 | CPU信号概念无用，或采样周期改到1ms就能廉价捕获微突发 |

Q是Folly未领取工作量代理，I是包装callback已开始未结束（含抢占/阻塞），O是已接纳未结束，R是投递预留。当前active评分为`(Q+I+R)/C`，不是仅I；outstanding为`(O+R)/C`。这些不是同一时刻的事务快照。允许估计误差仍需合法同步，不能用并发普通整数替代relaxed原子。

CPU亲和与内存位置是不同控制。真实worker构图可能在executor之前触页，绑定executor并不会自动搬动这些页面；生产agent要先确认分配/触页/共享路径及cpuset内存约束。[Linux NUMA内存策略](https://docs.kernel.org/admin-guide/mm/numa_memory_policy.html)

当前尚未得到通用“负载x → request p99”的公式。阶段3的条件分位/留出预测只对相应任务、线程与资源合同有效；DAG的p99由分支、依赖、未来到达及关键路径共同决定。下一批干预比较回答“使用哪项信号调度是否有净收益”，不是自动建立生产p99预测模型。

## 7. 工程、负载与后续路线

本次不修改Folly、C++路由、默认阈值或既有负载。新增矩阵线程维度，使同seed的各信号/线程case统一打乱，避免先跑完16线程再跑128线程；终端报告也将trace0未采集的迁移/跨NUMA显示为不可用，避免默认零误读。更新[下一步测试指南](TARGET_V2_SIGNAL_THREAD_GUIDE.md)。固定all-parent只是隔离信号效应，不是选定all为最优；均衡机会保持一致。

同步更新[生产agent手册](PRODUCTION_AGENT_PLAYBOOK.md)：阶段一只读发现本机事实，阶段二形成有限实验与参数合同，阶段三做可回滚工程和功能验收，阶段四在已授权范围做性能对照，阶段五按独立验证结果收敛。不同环境通过手工传递文档/终端即可；当地agent无法取得的材料标unknown，不能访问的目标不成为本项目所有工作的阻塞条件。

阈值给候选值与梯度：计数/容量类可从high=1、low=0.5的已实现参考点起步，在量纲/生命周期核对后有限探索；它们不是生产推荐值。work/CPU信号不得套用相同数字单位。持续时间门控没有实现，不给虚构CLI；首次实现要定义连续性、缺采样、快释放、危机旁路、目标保护，以及“hold到期是否还有新ready任务可迁”。

有限信号/线程对照之后，根据是否出现解释缺口选择短工作、同步阻塞反例、异步RPC驱动或工作集/跨NUMA实验。正式尾部和约1%小效应需要更长、交错、同工作重复以及未参与调参的数据；不以探索阶段的最大赢家直接上线。

无法给真实环境交接任何文件时，使用[纯prompt备选](PRODUCTION_AGENT_PROMPTS_ONLY.md)：背景、证据边界、五阶段操作和状态卡均内嵌在文字中；不假定对方拥有本仓库、不要求传业务源码或原始日志。当地产物可以仅打印成状态卡，供同一或不同模型继续。
