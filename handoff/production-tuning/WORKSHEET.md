## 3. A/B合同（02-design，运行前冻结）

```text

A配置ID与内容：

为何选B（本地证据，不只是demo收益）：

若无法固定：差异及如何限制结论

N：加一/所有权转移/释放符号；预留前或后快照；阻塞污染
C：资源域及容量定义；重叠如何处理
策略：home / 源阈值分流 / 目标约束 / 其他（写精确定义）
决策阶段：initial-only / every-ready / 其他
```

## 4. 终端简报（04-validate及05-iterate）

```text
实验ID/时间/代码版本：
负载：实际请求类型、到达QPS及初始fanout；有无重放，输入是否可比
资源：池数、worker数、有效CPU域、C与quota；其他干扰
A/B唯一差异：策略、阶段、目标范围、源阈值、目标cap
测量：预热/窗口；请求时延起止；CPU分母/口径；观察器开销

原始量                         A             B           变化/备注
请求接收/成功/失败/超时/未结束
实际输入QPS/完成QPS
请求均值ms / 请求p99 ms
请求样本n / 上侧1%约n*0.01
任务W均值 / X均值 / S p99 ms（诊断）
CPU并集平均% / 每域高占用最长窗口串ms
初始窗口CPU% / 后续窗口CPU%（注明相对窗口）
分流率 / 无目标回退率（注明分母）
N计数异常 / 正确性异常
内存 / 下游压力（按既有验收要求）

指标观察：N/Q快照位置、分桶覆盖和任务类型；仅在样本够时讨论条件p99
策略判断：通过/未通过/证据不足/不可比
当前实际部署/回退状态：
不能推出的结论：

原始配置、数据和详细报告的现场路径：
```

变化统一写`100×(B/A−1)%`并保留A/B原值；A为0时不算百分比。失败/超时不能因没有响应而从报告消失；p99若无法识别就说明边界，不伪造完成时间。每策略一次仅报告该轮观察，不编造置信区间。
