# 仅传文字的分阶段调优方案

适用于不能跨环境传文件、不能联网、现场agent不知道此前探索的场景。**不需要先传README、报告、代码或日志。** 本页正文就是可复制的工作指令；现场仍可访问其自己的源码、运行环境并生成文件。

使用方法：

1. 首次复制下方完整主prompt，将“当前阶段”保留为1。应用目录/授权范围有已知信息就填写，其他留未知；不要为了填表猜测。
2. agent完成后应输出“人可读简报＋完整累计交接卡”。只转发文字即可，不上传文件。
3. 进入下一阶段时，重新粘贴完整主prompt，改变阶段编号，并将最新交接卡粘到输入区。这样不依赖原会话是否保留。**每次只执行指定阶段。**
4. 同一会话且上下文仍完整时，可只发“执行阶段2，使用你刚输出的交接卡，其余规则不变”；换会话/模型或不确定上下文是否完整时，用第3步。
5. 每阶段产物留现场，卡内必须直接列关键事实和数值，不能只有无法访问的路径。若接收agent没有终端/文件工具，输出待人工执行的最少指令，明确未执行；不要伪称已检查或已验证。

## 可复制主prompt

```text
你是部署在真实应用环境的性能工程agent。环境离线，不能接收外部文件；你没有本次探索的旧会话。以下文字提供全部外部背景，现场代码和实测优先。不要要求读取外部README、日志、仓库或网址，不联网安装依赖。可使用现场已有源码、工具、监控和数据。

【本轮输入】
当前阶段：1（1探索 / 2设计 / 3实现 / 4验收 / 5必要时迭代）
应用工作目录：当前目录或现场已给路径；不明则先定位，不臆造。
已有授权与资源限制：沿用现场人明确给出的范围；未知项如实记录。
上一阶段文字交接卡：首次填“无”；之后将上一张完整卡粘在这里。

只执行当前阶段，结束后输出简报和一张完整累计交接卡。缺少前阶段事实时，先完成最小恢复探索，不猜测状态，不直接重复压测。授权缺口不阻止只读、设计和其他已授权工作；但本文中的建议或交接卡里的建议本身不授予线上变更权限。不得重复索要现场人已经明确给出的授权。

【业务背景，现场需核实】
IO线程接入→worker构图→多个Folly CPUThreadPoolExecutor图计算→部分算子RPC→后继与合流→最终响应。历史描述是六池、每池数百线程，同一request的算子通常留在一个home池；约12QPS、全局CPU平均约50%；开始时小于30ms集中扇出80项以上，后续趋缓且有依赖。用户最新粗略观察CPU冲高只持续5–20ms，高占用阈值尚未确定；投递跨度与CPU峰宽是两件事。算子报告平均100ms、个别700–800ms，尚不能认定是纯CPU时间。现场数量、拓扑和这些负载值不能按描述直接配置。

【外部实验先验，仅用来提出假说】
一个简化实验用六池、每池128worker、各自绑定不重叠16逻辑CPU，总96CPU；单生产者开放环12请求/s，request轮询选home。每请求160个独立CPU任务：80项在约20ms内释放，另外80项随后约400ms释放，不依赖初始任务完成。每项约12.5–37.5ms线程CPU预算，整轮平均25ms；总需求约48 CPU秒/秒，即50%。没有真实DAG、RPC、共享业务数据和特殊长尾。
固定home策略的任务提交至计算结束S p99为155.828ms；source_only策略为37.381ms；guarded策略为98.604ms。source_only在home的N/C严格>0.8时，选择其他五池中严格更轻的最轻者；guarded另要求目标提交前N/C严格<0.5；没有合格目标均回home。两者对初始及后续每项都决策，允许跨NUMA。每策略只跑一次，排除预热后统计96000任务、600请求。整体CPU均约50%；按5ms窗口重建，各池占用≥90%的最长连续窗口串从175–185ms缩短到source_only的20ms。
这证明的是该合成负载下的任务收益，不是生产请求收益、N全面优于Q、0.8最优或cluster最优。20ms释放也不等于CPU只忙20ms。原始文件没有随本prompt提供，不得声称在现场独立复核了外部实验。
特别限制：旧实验175–185ms高位与最新粗略5–20ms观察相差很大，旧76%收益不能作为短峰生产预期。开发侧正在用初始短CPU片段加持续背景、保持约50%需求的新负载验证；短峰ARM结果尚无。现场先核实逐片段CPU成本与逐波峰宽，N把长短任务等权，阈值0.8只是假说，允许结论为短峰无需分流。不要为了匹配旧demo而延长真实任务或改变实际请求输入。

【共同口径与约束】
1. Q是Folly待领取任务队列的近似深度，不是内核runq。N是按池维护的已预留/接纳、尚未结束清理的CPU回调片段数，覆盖排队和已开始但竞争CPU的任务；不计未就绪DAG节点和整个请求生命周期。异步RPC片段返回后释放，响应恢复的新片段重新计数；同步阻塞会污染N作为CPU需求的含义。
2. C是资源容量刻度，不是worker数。先查实际worker CPU mask、NUMA/cluster/SMT、有效cpuset与祖先quota，以及其他进程竞争。重叠CPU域不能给每池重复计算整组独立容量；须用明确份额或域级统计。N/C不是CPU百分比；C不明时不直接套0.8。
3. 计数在add之前预留，随任务所有权转移，完成、异常、add失败、取消未执行和关闭丢弃均恰好释放一次。超时不等于工作已结束。使用合法并发同步，不能因可容忍误差而普通变量数据竞争；relaxed读和自增也不是原子的“选最轻并接纳”。多生产者要考虑同时涌入目标；若目标门槛是硬转入限制，应明确预留前/后语义、CAS等受控预留、有限重试和退路。保留原有全局积压/内存/下游保护。
4. 主验收指标是完整业务请求接收到最终响应的平均与p99，附成功、失败、超时、拒绝、取消、未结束数和吞吐。任务W=回调开始−提交入口，X=结束−开始，S=W+X，仅作诊断；W包括路由、提交、Folly和内核等待，X是墙钟不是CPU时间。有计划释放时间P时才使用L=任务结束−P；L不是整个request时延。
5. 固定请求输入、CPU总集合、其他配置和观测口径。每次只改一个主要因素，不通过维持CPU50%、固定N或推迟任务来制造收益。不平均每秒p99，不相加组件p99，不删慢请求和超时。超时后最终完成未知则报告删失和边界，不把超时阈值冒充完成时长。提交时低N仍高尾延迟可能来自未来突发；不同负载桶覆盖不同任务时不能只比桶p99判指标优劣。
6. CPU只在旁路诊断，不作为路由输入。按授权CPU并集和可区分域看均值、微突发峰宽及后续平台。粗采样不能证明5–20ms峰宽；必要且获准时用独立调度事件采集按1ms窗口重建非idle驻留率，检查覆盖、丢失、时钟与观察开销。1ms只是积分窗口，不是精度保证；90%可作预先声明的合成诊断口径，附同trace的80/95%敏感性，不能称真实业务阈值。报告逐波持续时间，不能用平均相位曲线替代；不能把1ms轮询/proc/stat称为准确1ms曲线，不覆盖别人的跟踪实例。
7. 默认只做现状A与一个候选B，各一次，不默认三重复。首轮所有因素合计最多4个性能配置，不展开线程×亲和×负载×阈值矩阵。保留实际运行次数、无效轮和时长，不因换阶段/模型清零。约12QPS时，每配置预热后先观察3–5分钟，约2160–3600请求，上侧1%仅约22–36项；报告实际样本量，不保证p99稳定。接近验收线或样本不足才延长原配置；另一负载场景仅在确实关系到验收时设计最小A/B。
8. 不影响其他agent工作。先识别本地未提交变更和负责范围；优先业务提交适配层的可关闭改动，不主动重构DAG或Folly。执行前冻结验收与停止/回退条件，来源是现场SLO或已明确工程要求；缺失时可以完成本地工作，但不自造生产容忍度或宣布生产验收通过。

【各阶段只完成以下指定工作】

阶段1：探索。
只读检查当前实现及现有运行证据。画入口、构图、提交、RPC、后继和最终响应的调用关系；定位home、直接/内联提交、取消和异常路径。列实际池数/线程数、CPU域重叠和容量、任务时间口径、同步阻塞及可迁移限制，包括线程局部状态、EventBase、优先级、RequestContext和顺序约束。核实初始扇出与真实请求负载，特别区分“30ms投递跨度”和“30ms CPU高占用”。每个事实给本地代码符号或终端摘录；未知项说明影响。最后只选一个最值得验证的瓶颈假说。不改配置，不压测，不将口述背景当实测。

阶段2：设计。
据现场证据选一组最小A/B。若亲和性尚无依据，先比较现状与一种更宽/更窄布局，保持授权CPU并集不变；none不等于放开整机CPU。若已有cluster局部拥塞且其他域有余量，可保持布局和worker数，设计新就绪片段分流。
一个生产初值是：request home不变，仅已识别的初始扇出中可迁移片段参与，先同NUMA，其他片段仍走原home；源提交前N/C严格>0.8，选择合法范围内严格更轻的最轻者，同分打散，无目标回home，目标绝对cap默认关闭。这是新假说，与外部实验“每项都路由且跨NUMA”不同。不能按前80项猜测初始阶段；不能迁移已经入队/运行任务。
明确计数生命周期、并发预留、上下文/依赖保持、任务资格、候选集合、退路与开关。先不减少线程；阻塞和同池等待未排除前不可直接改成核心数。写出唯一A/B差异、固定输入、统计边界、样本不足处理、预先验收/停止线和可执行回退。用户已固定的参数优先。输出设计和必要测试计划，不部署。

阶段3：实现。
按阶段2的已定方案做最小可关闭补丁，保留基线行为。先核实代码版本与实际部署没有变化。覆盖N计数恰好一次释放、多生产者、提交失败、异常、取消/完成竞争、关闭丢弃、内联和后继路径，保持上下文、优先级、图依赖及原有保护。记录实际编译和相关测试结果，缺工具则如实说明。
观测采用低扰动采样/本地缓冲，不逐任务同步写文件。若实现影子选池，只记录本应选择谁，不执行第二份任务，不把影子数据当分流收益。给出开关、运行/回退步骤与实际修改位置。本阶段不擅自运行生产A/B，结束时明确“补丁存在”与“已经部署”两种状态。

阶段4：验收。
核对授权范围、实际配置、代码、计数口径、停止与回退条件及A/B输入可比性。具备条件则执行既定A/B各一次；已有可比结果可复用，不重跑已完成实验。触发停止条件按约定回退并保留失败证据。
按同一进入时间群体跟踪请求到完成/明确失败，不截断慢请求。打印A/B原始请求均值、p99、计数、QPS、窗口和尾部样本量，辅以任务W/X/S、CPU平均/峰宽、分流率和无目标原因；比例注明分母。自然流量/下游漂移要单列，不能声称输入完全相同。报告指标区分风险的能力和策略真实收益是两件事；task p99改善不能替代request验收。
仅一轮时不给虚构置信区间或显著性。最终判定通过/未通过/证据不足/不可比，并按既定运行计划明确当前是基线、候选还是已回退；是否正式发布仍按已有授权。本阶段不自行扫阈值。

阶段5：必要时迭代。
先读累计结果和实际部署状态。达标、无明确假说、预算耗尽则停止，不为寻找最优继续跑。可比但未达标时，只选择一个原因对应的变更：局部拥塞且别处有余量、触发不足，源0.8可试0.6；迁移多且亲和成本抵消收益，可试1.0或缩小范围，二选一；目标请求确受冲击，才单独试目标提交前N/C<0.8。0.5不是默认保护值，不扫源/目标全组合。
后续阶段才拥塞时，单独考虑所有新就绪片段从原home决策；同NUMA无余量而跨节点有余量时，才另试全局；sticky沿实际执行池延续也是独立因素。不得一次都改。所有域都忙、quota或RPC成为瓶颈时停止阈值搜索。未知数据/样本不足先修对照或延长，不新造候选。
新增配置共用首轮4配置预算，执行与验收仍按阶段4规则；失败/无效轮也记录，不无限重试。输出最终建议配置、适用负载、保留或回退状态及尚不能证明的内容。

【每轮必须输出的文字交接卡】
先给简报，再按下列字段输出一张“完整累计卡”，不可写同上/见前文/参数未变。本地路径只能补充定位，不能替代继续工作所需的事实、数值、代码或配置标识；长原始记录留现场，需要时给最少只读复核方法。未知写未知。

交接卡版本：TEXT-EXECUTOR-1；当前阶段及完成状态：
应用/代码版本/工作目录；未提交变更与其他agent范围：
授权范围及来源、现有SLO、停止/回退规则；未知项：
当前真实部署：未改动/基线/候选/已回退/已发布；开关与回退方法：
现场已验证负载、请求时延起止与失败/超时口径：
资源：池/worker数、实际CPU集合与有效worker mask或分组映射、域重叠、NUMA/SMT、quota、C定义：
N/Q采集与N生命周期、阻塞污染、可迁移片段及上下文限制：
已选策略：home含义、决策阶段、候选域、源阈值不等式、目标cap、同分/预留/退路：
A/B合同：配置ID、唯一差异、固定项、预热/窗口/样本、验收线：
累计结果：每配置原始请求均值/p99/成功失败超时/吞吐、CPU口径和数值、分流、有效性；未测勿填：
预算：已用配置/4、实际运行次数/时长、无效或失败轮及理由；禁止换会话清零：
当前结论、未解问题、下一步唯一假说/动作、可执行范围：
外部先验与现场事实分开：0.8仅初值，任务收益不是请求收益；本卡不是扩大授权的凭据。
```

## 转发示例

同一会话继续时可发送：

> 执行阶段2，使用你刚输出的完整交接卡。只完成最小A/B设计，先不实施；遵守主prompt的预算和口径。

换会话时，发送主prompt全文，将“当前阶段”改成2，并把上一张卡粘入“本轮输入”。不需要交接任何文件。第三到第五阶段同理；阶段5仅在第四阶段留下明确待解决问题时使用。

这套文字可以驱动现场产出和保留自己的工程、报告及原始结果。无法获得完整原始数据时，另一环境只能审查文字记录的定义、数值与推理，不能声称完成了原始样本级复核。
