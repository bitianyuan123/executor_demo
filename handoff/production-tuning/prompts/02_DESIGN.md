# Prompt 02：设计最小调优方案和验收标准

将下面正文复制给真实应用环境中的agent；这一阶段输出可实施设计，不执行生产变更。

---

你正在离线真实应用环境中设计Folly executor亲和性及负载分流调优。你可能没有任何聊天历史。先定位本交接包，读取相对于本文件的`../GUIDE.md`、`../EVIDENCE.md`、`../WORKSHEET.md`，再读取真实应用仓库中的`tuning-work/STATE.md`和`tuning-work/outputs/01-discover/`。如果前阶段产物缺失，先补齐影响设计的最小只读探索，不凭demo补造生产事实，不联网安装或clone。当前产物写入`tuning-work/outputs/02-design/`。

目标是降低**真实请求接收到最终响应**的p99，并守住既有正确性、错误率、吞吐和资源要求。合成demo只说明一种分流方向有价值：六个独立池、单生产者、无DAG依赖/RPC/共享业务数据时，N/C分流曾改善任务时延。不能直接推导生产请求收益。N/C不是CPU百分比；测试使用的CPU组、线程数、0.8和0.5都不是生产定论。

请依据现场实现设计一个最小、可回滚的候选，不修改代码、不开始运行实验：

1. **固定对照。** A使用当前实现；B只改变一个可解释的调度因素。先保留线程数、请求到达与任务内容、CPU总集合、其他资源和观测设置。若现场不能形成公平对照，先解决对照口径，不添加更多阈值点。
2. **选定亲和性方案。** 若当前已是cluster分池，首个生产候选可保留此布局和每request固定home，只允许经过确认的首轮扇出CPU片段分流；优先同NUMA其他池，后续就绪片段暂回原home。它是控制迁移范围的新候选，**不是demo已经验证的策略**。若现场不是这种布局，说明如何最小适配，不能强行改为六池或照搬CPU编号。明确哪些片段不可迁移、何时算“首轮扇出”。先不把放宽NUMA亲和、跨NUMA路由、worker数改变一起并入B。
3. **定义计数与容量。** 确定N的确切生命周期、池归属和是否存在同步阻塞污染；C先采用与现场不重叠执行资源匹配的容量刻度，记录逻辑CPU、SMT及配额局限。重叠CPU组不得简单各自宣称拥有完整独立C。Q保留作诊断；CPU占用旁路观测，不进入实时选池。异步挂起不计为持续CPU片段，恢复时新就绪片段重新计数。
4. **写清选池规则。** 若用户未固定阈值，源`N_home/C_home > 0.8`作为起始假设；在允许候选中选择严格更轻者，没有候选则回home。源阈值条件、候选集合、同分打散、预留时点、失败回退都必须明确。默认关闭目标绝对门槛，但仍比较目标负载；这不等于忽略目标是否繁忙。仅在出现目标受冲击证据时，单独试较宽的`N_target/C_target < 0.8`候选。历史0.5门槛仅为受限对照证据，不是默认推荐。用户若固定策略/阈值，尊重并记录，不擅自进入搜索。具体初始值与梯度以GUIDE和现场已批准设计为准。
5. **解决真实并发。** 生产可能多线程同时提交。设计选池后的计数预留、竞争失败重试上限和回退，避免所有生产者看到同一个旧最小值后同时涌入。近似读数不等于普通变量可以数据竞争。若要求目标门槛为硬约束，必须说明并发预留如何保证，并区分提交前/提交后的门槛；不要把一次快照检查称为长期容量上限。生命周期清理须覆盖提交失败、异常、取消、超时、关闭和未执行任务，保证每次预留恰好释放一次。
6. **固定统计与验收。** 主指标为请求均值/p99及失败、超时、取消、丢弃，任务W/X/S/L等仅在实际定义后辅助。采用相同请求群体、完整结束或显式失败计数，不删慢请求，不平均每秒p99。定义请求类型分层和时间窗口，记录吞吐、输入、外部服务、CPU平均与峰宽、迁移比例及回退原因。不要以维持N/C恒定来制造对照，这会改变输入。指出提交时快照只含当时信息，无法预测后续新任务冲击。
7. **控制实验规模。** 默认A/B各一轮，达到验收即停。只有明确待解决问题才追加；首轮最多4个性能配置，亲和性、线程数、路由和阈值共用这个预算，不各自展开矩阵。12QPS时，每配置预热后先观察3–5分钟，约2160–3600请求；报告实际样本数及最上侧1%约多少个请求，单轮不代表稳定尾部保证。更长的现有可比窗口可以复用；接近验收线或证据不足时才有理由地延长同配置窗口，不默认三次重复。只有另一负载场景关系到上线条件时才单独设计A/B，不默认追加。记录顺序和外部扰动；只有漂移确实威胁判断时才提议补一次对照。执行前固定已有SLO或经授权的停止/回滚条件、监测间隔、负责人、回滚命令与配置。

不要自造“允许线上p99恶化多少”“允许丢请求多少”或部署授权。既有授权有效；权限不足时仍完成设计、补丁规划和本地验证计划，将生产执行缺口单列。不要把设计参数数量增加当作进展。

请输出：

- `design.md`：明确A/B差异，路由流程、N生命周期、并发预留、候选资格与回退伪代码，亲和性影响和已知风险。
- `experiment.md`：一组最小A/B配置、固定因素、测量口径、样本充分性与无结论处理。
- `acceptance-and-rollback.md`：有来源的验收要求、执行前必须具备的停止/回滚条件和授权边界。
- `implementation-plan.md`：拟修改的真实文件/符号、开关、兼容行为、必要测试，不复制demo为生产实现。
- 更新`STATE.md`：已确定的参数、仍未知的参数、下一阶段的可执行范围和文档路径。

最后明确“可进入实现的内容”和“需要现场决定的部署事项”。阶段02结束后等待阶段03指令；不自行执行A/B或线上变更。
