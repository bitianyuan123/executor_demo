# Prompt 04：执行最小A/B并形成可判定报告

将下面正文复制给真实应用环境中的agent；只执行已设计、已授权的验收范围。

---

你在离线真实应用环境中验收Folly executor调度改动。先定位交接包，读取相对于本文件的`../GUIDE.md`、`../EVIDENCE.md`、`../WORKSHEET.md`，以及`tuning-work/STATE.md`与`tuning-work/outputs/01-discover/`、`02-design/`、`03-implement/`。当前结果写入`tuning-work/outputs/04-validate/`。若实现、停止/回滚规则、测量口径或部署授权缺失，先补齐可在本地完成的部分，不直接开始生产试验；已有授权不重复申请。不联网安装或访问别的环境，不假定存在外部历史数据。

本阶段只回答：在实际负载、既定资源下，候选B是否比现用A改善**请求级**时延，并且没有破坏已约定的正确性和资源约束。默认A/B各一轮，不自动三次重复、不顺便搜索阈值。达到验收即停；确有明确问题才进入阶段05，首轮累计最多4个性能配置，亲和性、线程数、路由和阈值共用预算。另一负载场景仅在关系到上线条件时另行设计A/B，不作为默认附加项。

执行前确认并记录：

- 代码/配置版本、运行模式、实际worker数、每线程允许CPU、进程CPU配额、N/C的C定义、候选池范围、源/目标阈值及不等式、开关状态。不要仅凭配置文件宣称affinity已生效。
- A/B输入请求类型、QPS及到达形状、数据集/缓存状态、外部RPC、CPU总集合和观测开销如何保持可比；线上自然流量不能重放时明确其限制，不能宣称完全相同输入。
- 主统计群体、预热、观察窗口、请求数、样本不足规则，以及尾部请求如何完整结束或计为失败。12QPS时每配置预热后先观察3–5分钟，约2160–3600请求，实际最上侧1%只有约22–36项；报告实际数值，不把这个规模当作稳定p99保证。可以复用更长且可比的已有窗口，接近验收线或证据不足时才延长。停止/回滚条件须来自阶段02已认可规则；不能临时放宽。若仍缺实际生产SLO或可接受变化范围，不能自行发明，先执行已授权的较低风险验证或输出待执行清单。

运行与收集：

1. 按已批准计划运行A和B，实时监看停止条件；触发则按runbook回滚、保留原始证据，并停止当前候选。不得隐瞒失败轮或通过删除慢请求获得“收益”。
2. 记录请求接受至最终响应的均值/p99、成功/失败/超时/取消/丢弃、输入与完成吞吐、观察窗口与排空情况。p99从完整个体请求或可合并直方图计算，不平均每秒p99，不把各组件p99相加。请求类型与完成状态的口径要一致；超时不能简单从所有延迟指标中消失。
3. 辅助记录任务等待/执行墙钟、线程CPU时间（若已有低扰动采样）、Q/C、N/C、实际迁移比例、来源/去向、回退原因、阻塞占比和N最终状态。记录负载快照是在当前任务预留前还是后，关联当前任务和请求，不用事后信息回填提交时指标。
4. CPU按实验CPU并集、NUMA和可区分的池/cluster观察：平均值、微突发峰宽、后续平台，说明采样/事件重建口径。CPU不参与路由。没有权限或高精度事件丢失时如实降级结论，不把5ms轮询`/proc/stat`冒充精确5ms占用，也不对重叠CPU组重复加总容量。
5. 原始数据留在现场，输出可终端打印的紧凑表和证据路径。无需上传文件；报告保留参数、分母、请求数、时间窗口及异常，支持人工复制回顾。

分析时必须分开两件事：

- **指标有效性：** 在固定配置/负载条件下，提交时N/C或Q/C对后续任务/请求风险有多少区分能力，是否只反映提交顺序，是否受后续突发干扰。分桶报告样本数和条件均值/p99；低读数仍有高尾时解释未来到达、共享资源、RPC及关键路径，不武断否定/肯定指标。小样本仅描述，不做稳健尾部结论。
- **策略有效性：** 使用该指标的B是否降低真实请求p99，迁移是否增加跨NUMA访问或破坏后续局部性。任务p99改善但请求p99不变须保留这一结论；它可能反映关键路径不同，不能以任务结果代替请求验收。

每组只有一轮时不声称显著性、稳定重复性或全局最优。请求数或尾部信息不足时明确“证据不足”；需要继续可有理由地延长相同配置观察，而不是自动新增梯度或重复三轮。出现输入漂移、CPU竞争或下游异常，标记不可比并解释最小修复方案。

请输出：

- `raw/`：实际原始日志/配置/摘要或现场已有数据的不可变定位。
- `report.md`：先定义负载、资源、N/Q/C和策略，再列A/B原始值、相对变化、CPU观测、请求与任务指标区别、局限和验收结论。
- `terminal-summary.txt`：可直接打印的精简参数表、原始结果、CPU摘要和结论；不能只有百分比收益。
- `decision.md`：通过/未通过/证据不足/不可比四者之一及依据；如需迭代，只列一个最主要假设和最小下一步。
- 更新`STATE.md`：实际部署状态、回滚状态、实验标识、结果路径和阶段05输入。

阶段04结束后不自行扩大矩阵或正式推广。已有明确发布授权且验收条件满足的后续操作按授权完成；除此之外，提交可复核结果等待下一阶段。
