# 现场 agent 必须知道的实验事实

本文件把既有探索压缩为可离线阅读的证据。**观察值、机制解释和生产候选不是同一层结论。** 不需要访问原仓库或历史会话。

## 1. 问题来自什么业务

原始业务：IO 收请求 → worker 构图 → executor 图计算；图开始阶段短时间扇出 80 项以上，后续有依赖、继续唤醒算子，部分算子通过异步 RPC 调用下游。应用约 12 QPS、整体 CPU 平均约 50%。executor 分为六个 Folly CPUThreadPoolExecutor，同一请求通常进入同一个池，每池数百线程。算子报告平均约 100ms、少数 700–800ms，**这些时长是否为纯 CPU 时间必须现场重新核实**。

历史 cluster 绑定曾观察到 CPU 使用下降但时延略升，且波动较大；这些观察没有证明某种亲和性最优。真实数据共享、同步阻塞、拓扑与资源隔离状态仍需从现场获得。

## 2. 最新一轮 3005 测的是什么

|项目|实际设置|
|---|---|
|线程池|六个原生 Folly CPUThreadPoolExecutor，每池固定 128 个 worker|
|CPU|每池独占一组 16 个逻辑 CPU，共 96 个；三个 cluster/NUMA，两个 NUMA|
|历史 CPU 编号|池0…5分别为0–15、16–31、32–47、192–207、208–223、224–239；NUMA分别0、0、0、2、2、2。不得套用到生产机|
|请求到达|单生产者、开放环、固定 12 请求/s；请求 b 的 home=b mod 6；不同 home 波次错开83.333ms，同 home 每500ms一波|
|每请求的任务|160 个相互独立的 CPU 回调，无 DAG 依赖、RPC 或共享业务数据|
|初始80项|第 j 项在请求到达+j×0.25ms投递，j=0…79，计划跨度19.75ms|
|后续80项|第 k 项在到达+20ms+k×5ms投递，k=0…79，最后415ms；不等待初始项完成|
|单任务工作|整数忙循环；按线程 CPU 时钟消耗预算，约12.5–37.5ms随机，整轮平均精确归一25ms；不是sleep，不是固定墙钟25ms|
|平均需求|12×160×0.025=48 CPU秒/秒，约为96逻辑CPU时间的50%；不是根据CPU反馈限速|
|对照|同seed52000、同任务/计划时刻/预算/CPU/线程/观测；仅改变选池规则，每策略一轮|
|统计集合|60秒运行，预热10秒；按请求计划到达在[10,60)选600请求、96000任务，迟到投递和晚完成任务仍保留|

这里把预算缩到25ms，是为了同时保留每请求160项、12QPS和约50%平均需求。若160项全部是100ms纯CPU，需求将达到192 CPU秒/秒，即96逻辑CPU的200%。本轮**没有复现原算子耗时分布和700–800ms长尾**。

## 3. 术语与计量边界

|量|定义|
|---|---|
|Q|路由时通过 Folly `getTaskQueueSize()` 读取的近似待领取任务数；不是内核 runq，不含已经取走的回调|
|N|每池已预留/接纳但尚未退出清理的任务数；选池后、add前+1，回调清理−1，add失败回退；已开始但被抢占的任务仍在N内|
|C|本轮每池16的容量刻度；不是128线程，也不等于16物理核心的吞吐|
|N/C、Q/C|任务项数/容量；不是CPU百分比。所有读数在本任务预留之前获取，不含本任务，分别读取且非全局一致快照|
|home|请求创建时确定、分流后不变的原亲和池|
|source / target|当前项默认进入的home / 本次真正选择的提交池；source不是上一算子实际所在池|

`submit` 在应用提交路径入口，早于读取负载、选池、预留和 Folly add；`start` 在回调开始，`end` 在计算结束、清理 N 之前。P 是**这一项任务**的计划释放时刻，不是请求到达时刻。

|时间量|公式与解释|
|---|---|
|W|start−submit，含路由/提交、Folly排队唤醒、内核调度等待；不能全部称为Folly队列等待|
|X|end−start，回调墙钟时间，含获得CPU计算和被抢占的时间；不是纯CPU预算|
|S|end−submit=W+X，任务提交到计算结束|
|L|end−P，任务计划释放到计算结束，用于检查投递迟到；**不是完整request端到端时延**|

p99对该策略全部入选任务排序取第ceil(0.99×n)项；不平均每秒/每桶p99，W和X的p99不能相加。真实业务验收必须另测请求接收至完整响应，或明确标注为图级时延。

## 4. 三种策略的精确定义

|策略|规则|
|---|---|
|`home` 固定原池|全部任务提交原home|
|`source_only` 源阈值分流|home的N/C严格>0.8时，扫描其他五池，选择严格比home轻的最轻池；无目标绝对cap；无更轻目标仍留home|
|`guarded` 双阈值分流|同上，但目标还必须满足提交前N/C严格<0.5；无合格目标留home|

C=16时，源N≥13才触发；目标<0.5允许提交前N≤7。source_only仍然读取并比较目标负载。“guarded”这个名字不代表安全性已经得到证明。0.5是快照准入条件，不是池永远不超过该值的硬上限。

三个策略固定相同 cluster 绑定。两种分流都覆盖 initial 和后续每一项任务，从原home重新决策，可去其他五池、允许跨NUMA；没有同NUMA优先，没有按上一算子目标粘滞执行。不移动已入队或正在执行的任务。本轮只有单生产者；多生产者争抢目标尚未验证。

|S均值|64.052|39.920|25.101|
|S p99|155.828|98.604|37.381|
|L均值|64.409|40.118|25.293|
|L p99|156.032|98.736|37.575|
|W均值|16.221|5.854|0.022|
|X均值|47.832|34.065|25.079|
|96CPU平均占用，5ms事件重建|50.481%|50.362%|50.219%|
|96CPU平均占用，100ms累计计数|50.474%|50.322%|50.380%|

|分流任务比例|0%|20.5%|44.1%|

source_only相对home的S p99下降76.011%；guarded下降36.722%。guarded有33.4%的全部任务因目标门槛不满足而留home，占源阈值已触发任务的62.0%。这支持“本轮目标0.5限制分流”，不等于“所有业务都不需要目标约束”。

按每请求到达对齐、观察其home CPU，窗口平均占用如下：

|策略|0–30ms|30–100ms|100–200ms|200–300ms|300–420ms|
|---|---:|---:|---:|---:|---:|
|home|93.434%|99.976%|80.519%|31.653%|31.896%|
|guarded|93.985%|96.603%|43.910%|39.984%|38.284%|
|source_only|82.721%|44.345%|58.248%|51.667%|45.422%|

20ms内投递不等于CPU只忙20ms。初始80项×25ms需要2 CPU秒，在16逻辑CPU上仅这批就至少125ms；加上后续需求，持续高占用更长。因此本轮没有复现“真实业务高占用只持续约30ms”的全部特征。全局平均50%也不意味着突发后每池稳态50%。

5ms来自`sched_switch`进出idle事件积分，是非idle驻留率，不是每5ms轮询`/proc`。idle期间中断未单独计入，steal未校正；两类CPU口径不同。三次捕获均96/96 CPU覆盖、9999/9999完整窗口有效、无报告丢失。原始逐项数据和trace未传回本地，本包保留终端汇总，p99没有在这里重新从原始任务计算。

观察器进程整轮CPU时间约18.2–23.1秒，尚不含全部内核事件开销；不得称零扰动。全部策略使用相同采集。CPU只作诊断，不参与路由。

## 6. 能支持什么，不能支持什么

- 支持：局部CPU持续拥塞可与全局约50%均值共存；本轮用N/C向更轻池分流能缩短任务时延，较严目标cap会错过可用资源。
- N值得优先验证：Q看不到已取走但竞争CPU的任务，N仍覆盖它们；应用层维护成本可控，但不是已测得固定纳秒数或零开销。
- **没有证明N总比Q预测得好。** 本轮没有Q驱动策略的严格同条件对照。后续阶段低N/C桶S p99约37.324ms、低Q/C桶约71.860ms，但覆盖率约60.15%与81.17%，不是同一任务集合，不能直接排名指标。
- 初始阶段N/C<0.5的桶S p99仍约115.919ms：这项提交后，同波未来任务继续加入竞争。当前快照不是未来p99保证；不能为了让曲线好看改成固定N发压，再称原业务验证。
- **没有证明**0.8最优、cluster优于NUMA/none、同NUMA优于跨NUMA、initial-only优于every-ready、sticky优于home-return，也没有测出生产完整请求收益。
- 生产中的RPC等待、内存/缓存、任务异质性、同步依赖和多生产者可能改变结果。真实请求尾时延及正确性优先于demo任务p99。
