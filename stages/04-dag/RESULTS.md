# 阶段4：复杂DAG实际验证

本轮40个串行实验、1,440个request全部完成，0拒绝/取消/失败。每轮3秒、12 request/s，两个逻辑CPU分区；每配置2个seed。图基线为三波40/10/10，每波深度1，共60个算子和3个join；每算子名义CPU 2000μs、每join 100μs。只对tail/RPC场景单独增加对应变量。

单NUMA开发机的none和numa都使用相同CPU并集；它们的时延差属于重复运行差异，**不能叫NUMA收益**。cluster参数仅代表两个明确CPU分区，不是实际ARM cluster。所有结论限于这个合成模型。

## 1. 基线、后续fork和亲和策略

下表平均/p99来自每配置合并的72个完整request；p99样本很少，接近最大值，仅供机制观察。

|配置|平均ms|p99 ms|
|---|---:|---:|
|分区固定home，每池2线程|61.115|73.343|
|分区固定home，每池16线程|63.830|77.276|
|每池16线程，borrow，每次就绪重新偏好home|36.601|54.664|
|每池16线程，sticky，跟随实际parent|37.078|56.528|
|每池16线程，仅初始fork均衡|45.581|63.069|
|每池16线程，每波fork均衡|36.663|61.290|

路由组使用queue指标，先验证低成本信号。多波图中只分散初始fork，后续波可能重新集中在join parent附近，因此允许后续fork再均衡在本例有收益。这个结果不能推出任意后继都要迁移，更不能定量预测真实跨NUMA代价。

## 2. 总工作量相同，图形仍改变关键路径

四种图都为60个算子和3个join，同seed使用相同名义工作序列。深链形状为每波5条分支、每分支4个算子；宽度更小、依赖路径更长。

|图形|home平均ms|borrow平均ms|
|---|---:|---:|
|前重40/10/10|63.830|36.601|
|均匀20/20/20|63.572|35.943|
|后重10/10/40|62.755|35.995|
|深链5×4、5×4、5×4|65.433|49.985|

深链可并行宽度下降后，借用其他CPU的收益也缩小。对真实业务应同时采集总CPU需求、初始就绪宽度与关键路径，不能只用“节点数20～400”建模。

独立压力场景：2%×8长尾下home/sticky均值为73.761/45.535ms；35%算子20ms异步RPC下为110.497/100.736ms。它们使用固定2000μs工作估计和work指标，不能把它们相对queue基线的全部差异归因于RPC或长尾单一因素。可以在各自场景内对照策略；目标机应继续拆分估计误差与服务机制。

## 3. 每条依赖和完成路径都核验

40轮全部经过独立依赖分析，共检查1,440个完整图、123,936条CPU阶段依赖边。分析器从配置重建预期图，拒绝缺边、多余边、重复节点和错误执行顺序。

一个home/16线程轮次的平均请求64.274ms，被分解为：

- 到达、依赖满足至提交和异步衔接间隙：0.151ms。
- 决定本次完成时刻的路径上submit→start：40.571ms。
- 同一路径的CPU阶段执行墙钟：23.552ms。
- 请求收尾：约0.00007ms。

这些逐请求分量相加等于请求时延。同轮所有并行节点的submit→start之和平均为661.364ms，**不能直接加到64.274ms的请求上**。执行墙钟与线程CPU的差也不能全部命名为内核runq；这里未对新的40轮打开详细内核追踪。

## 4. 补充：固定12 QPS，增加请求重叠

前述缩短算子预算的基线中，许多request小于83.3ms到达间隔，更直接验证的是单请求内部burst。为了另行验证多个request相互重叠，增加8轮，每轮6秒、12 QPS、每算子4000μs，图形和各组CPU资源保持不变，共576个request全部完成。

|策略，每池16线程|144个request平均ms|合并p99 ms|两轮观察到的最大同时在途request|
|---|---:|---:|---|
|固定home|135.553|422.719|5 / 2|
|borrow|70.691|123.912|2 / 2|
|sticky|71.273|161.515|2 / 2|
|每波fork均衡|73.066|224.583|3 / 2|

这里更快的完成会自然减少同时在途请求数；它是结果，不是闭环发生器主动减少投递。home两轮均值146.904/124.201ms，波动不小，不能把合并p99当成精确稳定尾部收益。完整[请求重叠对照](../../results/staged/analysis/dag-overlap-summary.md)和[在途区间统计](../../results/staged/analysis/dag-overlap-summary-concurrency.json)保留逐轮数据。

连同主矩阵，阶段4共48轮、2,016个request，全部依赖核验通过；按配置重建的CPU阶段依赖边共170,016条。

## 5. 仍然保留的限制

CPU预算模式保证目标预算一致，但实际CPU可能因计时粒度、调度和循环退出检查超过目标；它不是固定指令工作量。真实缓存/NUMA成本应按指南改用固定迭代或真实算子，验证内存放置。本轮没有真实下游RPC、任意DAG导入、业务内存共享或目标机PMU数据，72请求/配置也不足以检验0.5%～1%的收益。

工程与测试可用于分步验证；生产决策仍需真实六池三绑定、足够长稳态窗口、独立重复、CPU/请求和拒绝率等联合证据。能力放在业务侧还是Folly的比较单独见[阶段5](../05-placement/README.md)。
