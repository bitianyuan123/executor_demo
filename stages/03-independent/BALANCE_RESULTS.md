# 阶段3负载指标与均衡：开发机验证记录

## 结论与适用范围

**优先进入ARM验证的候选是`outstanding/C`：它覆盖已开始但尚未结束的任务，只需每池计数，不要求提前知道算子耗时。** 本次Poisson观测中，它确实提供了queue缺失的信息；固定预算突发组中，按它分流也明显降低了完成时延。但queue分流和静态spread同样有效，不能把全部收益归因于新指标，也未证明N是所有负载下的最佳指标。

这是共享x86开发虚拟机的工程与机制验证，不是用户的隔离ARM结果。实际环境4个逻辑CPU、约7.5GiB内存；实验只用CPU0、1，两个池各绑1个逻辑CPU，使用nice 10。没有假称这些人工分区是物理cluster，也没有排除其他宿主干扰。主任务均值2ms，另补20ms观测；ARM仍应使用原主组100ms、6池、96逻辑CPU配置。

完整原始CSV、metadata、summary、逐轮日志、计划与分析结果见[证据包](../../results/stage3-balance-20261115/README.md)。累计169轮全部完成，分析没有无效或缺失轮；这不等于全部结果已达到性能确认所需的时长与尾样本量。

## 1. 实际完成的矩阵

所有策略先生成相同planned到达、任务CPU预算及估计预算，同seed内随机顺序、串行运行；以planned窗口选任务，保留窗口后完成的任务。

|组|线程/池|负载|时长/分析窗口|种子|轮数|
|---|---|---|---|---|---:|
|observe|1、16|2ms，160 task/s；local20、smooth、spread20|3s / [0.5,3)|11000–11002|18|
|observe-progress|1、16|2ms，local20，进度发布500µs|3s / [0.5,3)|11000–11002|6|
|observe-long|1、16|20ms，16 task/s，local20|8s / [1,8)|11000–11002|6|
|observe-poisson|16|20ms，64 task/s期望值；Poisson smooth与spread20|6s / [1,6)|11000–11002|6|
|tune|1、16|2ms local20；home/spread/Q/N/R阈值网格|3s / [0.5,3)|21000–21002|48|
|evaluate|16|冻结N/C=2与Q/C=2、home、spread|3s / [0.5,3)|31000–31006|28|
|minimal|16|冻结策略；原instrumentation=none，各指标匹配home|3s / [0.5,3)|32000–32002|15|
|cost|16|固定迭代工作，off/basic/progress/minimal及匹配路由|2s / [0.5,2)|41000–41002|42|

第一组进度发布间隔为5ms，大多2ms任务在首次发布之前结束，因此R近似完整估计B；保留此组作为盲区示例。后续2ms组改为500µs，20ms观测用5ms。所有估计主组为常量类别均值，故完整估计B与N仅为常数缩放。

observe-poisson的名义总需求为1.28 CPU秒/秒，其他CPU预算组为0.32 CPU秒/秒；不把两者混合拟合。Poisson任务数量跨seed变化，仍保证同seed策略配对序列相同。短Poisson spread轮出现明显尾部积压，其预测关系也可能包含时间变化；不能称为稳态容量曲线。

## 2. 哪个指标更有信息

最能展示queue盲区的是Poisson smooth、每池16线程但仅1个CPU、均值20ms的组。三个seed共958个窗口内任务；每轮queue只有一个值（0），相关系数为NA。outstanding/C与planned完成时延的Pearson分别为0.639、0.631、0.602；remaining/C分别为0.696、0.639、0.618。相关性不是因果，也不能把每条任务称为一条“p99样本”。

下表为**整seed留出、训练seed确定分桶、测试seed评估**的三折等权结果，预测目标为planned→end。分位损失越小越好；coverage是预测条件p99的覆盖率，需与目标0.99和样本量一起判断。

|Poisson smooth指标|均值预测MAE ms|p99 pinball ms|p99 coverage|
|---|---:|---:|---:|
|queue/C|15.950|0.886|0.9868|
|outstanding/C|12.319|0.654|0.9866|
|remaining/C|12.045|0.689|0.9876|

N使MAE下降约22.8%、p99分位损失下降约26.2%；R的均值预测略好，但该组p99损失反而略高。完整work与N等价。这里单轮只有311–336个任务，p99证据很弱，分析明确标记LOW_TAIL。池负载与自身任务预算联合建模的结果也保留在prediction.csv，合成真实预算只标作oracle。

Poisson spread20组的完成MAE：queue 110.543ms、N 76.171ms、R 83.347ms；等待MAE：queue 43.475ms、N 30.850ms、R 22.344ms。最佳信号随目标改变，不能从一个相关系数选出通用赢家。

对比之下，regular local20、2ms短任务组中，16线程配置的完成MAE为queue 6.346ms、N 6.282ms、R 6.341ms，差异很小。20ms regular local20组中，单指标仍明显受同批未来投递和自身预算影响。**本实验没有隐藏“不明显改善”的配置，也没有要求所有情形线性相关。**

## 3. 简单分流的收益

基于tune的三轮短测，冻结N/C阈值2，并保留同阈值queue参照；选择理由是N覆盖在途回调且维护简单，并非已证明它最优。随后使用7个新seed复验。每轮480个计划任务，分析窗口400个；下表是逐轮统计量的等权均值，**p99列不是把7轮任务合并后计算的总体p99**。

|策略|planned均值 ms|每轮planned p99的均值 ms|平均路由计时 ns|
|---|---:|---:|---:|
|home|25.762|43.355|84|
|queue/C > 2|14.030|23.984|127|
|outstanding/C > 2|14.112|23.170|129|
|静态spread|14.291|24.789|120|

N相对home：逐seed平均改善率约45.2%（均值）、46.5%（p99）；p99配对差均值−20.185ms，按7个seed重采样的95%区间约[−20.763, −19.722]ms。这个区间仅描述本短实验的重复，不涵盖不同硬件、生产任务或系统干扰。

直接按相同seed比较N与queue，均值差为+0.082ms、p99差为−0.813ms；N与spread的均值差为−0.180ms、p99差为−1.619ms，后者p99配对区间跨0。原始逐轮差保留。**现有证据支持分散局部突发的收益，不支持宣称动态N策略稳定优于静态spread。** 在本组中N约49%的任务离开home，spread固定约50%；没有模拟缓存亲和损失。

minimal单指标模式的另外3个seed中，N相对匹配home的均值差−11.650ms、p99差−19.962ms，仍有明显分流效应；仅作描述性复验，不与progress组混成10个重复。

## 4. 成本不是免费的

CPU时间预算模式会把回调内的观测CPU消耗吸收进固定预算，所以另以相同迭代数测量。这里64 iterations/µs仅是工作量换算，实际服务CPU时间远小于标称2ms，不能把它当实测2ms。

三个seed中，home/minimal-N相对home/off的进程CPU/完成任务差约+0.003ms；minimal-queue也约+0.003ms。minimal-remaining约+0.096ms，progress约+0.095ms，主要说明额外高频线程CPU时钟读取不可忽略。这里包括采样线程、计时和共享状态维护，不能把+0.003ms解释成一次atomic指令的成本。

off基线seed41002的p99为18.382ms，另外两轮约5.4–5.6ms。这个异常导致若干“观测成本”的p99差为负，原始结果保留；**负差不代表计量能提升性能，也不应删除这一轮。** 更长且隔离的ARM固定工作量对照用于判断净成本。

## 5. 编译、功能和来源

- 工程独立Release编译，最终7/7 CTest通过；新增统计防错测试20项、矩阵测试10项，并验证小数容量往返、拒绝/取消/异常回收、remaining估计不足等路径。
- 169轮性能实验的C++源码对应提交`7227e2d`，二进制SHA256为`ee790967c923dfc9f191aee4bc544b4aa65210b7c945c669998c6e2e26915159`。随后修复了非整数容量的输出精度并重新编译测试；现有矩阵均使用整数容量，结果仍保留原二进制来源，不冒称为新二进制重跑。
- Folly依赖来自已有安装的独立副本，静态库及相关配置/核心头文件哈希另存于证据包。没有重新构建或修改共享Folly安装，也没有修改DAG工作树。
- 所有终端摘要与完整报告均可重算。正式ARM执行按[运行指南](BALANCE_GUIDE.md)先observe，再tune/freeze/evaluate；不能直接把开发机阈值2当成已在ARM验证过的最优值。

进入ARM后最关键的验收是：256线程时N是否仍改善整seed预测；N分流能否优于home、queue及spread；收益是否经得住minimal/固定工作量成本和none/numa、长尾、估计误差等对照。阶段3不验证request亲和、图依赖或迁移后缓存代价，这些仍由DAG阶段负责。
